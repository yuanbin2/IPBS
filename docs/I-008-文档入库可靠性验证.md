# I-008 文档入库可靠性验证

日期：2026-10-23。对象是本地 `Document` 的 Celery 入库；`target=ragagent` 的远端上传不走此链路。

## 已有机制与本轮修复

上传先保存 `Document`、源文件引用和 `DocumentIngestionJob`，事务提交后投递。Job UUID 同时是任务 ID；30 秒一次的 beat 扫描未投递、到期重试及租约过期任务。每个文档按 `desired_ingestion_generation` 排队，构建在事务外完成，最终在事务内检查代际和 attempt，再切换 `active_ingestion_generation`；检索只读取有效代际。`(document, generation, chunk_index)` 唯一约束和已完成任务幂等返回防止重复有效切片。重建失败时保留上一个有效索引。删除文档级联删除任务与切片，旧任务不能再写入。

本轮发现并修复：

- 入库任务原来没有执行时限。现在软限制 8 分钟、硬限制 9 分钟，低于 10 分钟数据库租约。软超时保存 `ingestion_timeout` 后按退避重试；硬杀或进程丢失由租约到期后的 outbox 扫描接管。Celery 的硬/软时限需在部署使用的 Linux prefork worker 中实测，不能凭配置断言 Windows solo worker 的行为。
- 旧 broker 投递异常原来只按 `queued` 状态写回，可能覆盖同一 Job 的后续 attempt。现在同时检查 attempt。同步发布关闭 Celery 自身重试，交由持久化 outbox 调度。
- 旧消息原来能在 `pending`/`retry` 或 `processing` 租约过期时直接再次执行，绕开退避与 attempt 上限。现在 worker 仅消费 outbox 已租约投递的 `queued` attempt；其他非终态消息延后或作为重复消息返回。
- 删除与解析交错时，旧 worker 可能因找不到 Job 抛异常并误报重试。现在缺失 Job 安全退出；已删除任务的查询返回 404，不回退到不带 workspace 限制的 Celery 结果。

## 状态、重试与恢复

`pending` 为持久待投递，`queued` 为 broker 投递中的租约，`processing` 为 worker 持有租约，`retry` 为有确定到期时间的退避，`completed`、`failed`、`superseded` 为终态。状态查询：`GET /api/agent/tasks/<job_uuid>/`，仅同 workspace 的 operator 可见。已删除任务返回 404。

最多 **5 次 attempt**，包括 broker 发布失败和 worker 执行失败。失败后的等待为 30、60、120、240 秒（代码有 15 分钟上限，当前 5 次尝试不会触及）；beat 每 30 秒扫描一次。worker 硬杀时无即时错误记录，10 分钟租约到期后扫描重新投递，最多约再等待一个 beat 周期。耗尽后 Job 留在数据库的 `failed` 状态，包含固定失败码、attempt 数和完成时间；这是数据库中的失败任务记录，**未配置 RabbitMQ 死信队列**。有旧索引时旧代际仍可检索；首轮入库失败则文档为 `failed`。

恢复操作：先按任务 UUID 查询状态和 `failure_code`，检查 worker/beat、broker、数据库与源文件，再等待未到期的 `retry` 或租约。确认 `failed` 后，以原 workspace 的 operator 调用 `POST /api/agent/documents/<document_id>/reindex/` 建立新代际和新 Job；核对新任务 `completed`、`active_ingestion_generation == desired_ingestion_generation`、有效切片数量与检索结果。不要直接把旧 Job 改成 `queued`、手工清空 attempt 或重放已删除文档的任务。文档或源文件已删除时需重新上传；旧任务 ID 不可用于恢复。人工重建与 broker 恢复不会修改上一个有效代际，直到新代际完整提交。

## 本地已运行的验证

根 `.venv`，`BLOG_LOCAL_MODE=1`、`LANGCHAIN_TRACING_V2=false`、`LANGSMITH_TRACING=false`；Django 使用临时 SQLite 测试库，本地哈希 embedding，broker/worker 由 mock 或 eager 路径替代。

| 场景 | 结果与边界 |
| --- | --- |
| 上传保存后 broker 发布失败 | 文件字节、Document 和 Job 可查询，状态转 `retry`；之后调度可继续。使用 mock 发布故障。 |
| 重复投递与代际切换 | 完成任务再次执行不增加切片；重建期间旧代际即使构建完成也不能激活；不同 workspace 检索隔离。确定性交错测试，并非真并发。 |
| worker 丢失、软超时、旧消息 | 租约未到期不重新投递；到期扫描增加 attempt；软超时记 `ingestion_timeout`；旧消息不能绕过退避。超时由异常注入，硬杀由租约状态模拟。 |
| 删除与旧任务并发 | 构建中删除后，旧任务返回 `deleted`，不产生切片；删除后任务 URL 为 404。确定性交错测试。 |
| 耗尽与恢复入口 | 第 5 次 broker 失败进入 `failed`，文档有失败码；原有重建 API 可创建新代际。未实测真实 broker 断线。 |

## 待执行的隔离真实服务故障验收

本机 Docker CLI 存在，但 Engine 管道不可连接；`127.0.0.1:5432`、`:5672` 无服务。本轮未启动 PostgreSQL、RabbitMQ、Redis、Celery worker/beat，也未对现有数据做操作。以下步骤必须在**全新隔离数据库、broker vhost、媒体目录/卷和容器项目**中进行。仓库主 `docker-compose.yml` 有固定 `container_name` 和宿主端口，直接换 `-p` 不能保证与现有环境隔离；先复制配置并改为唯一容器名、独立卷，去掉宿主端口映射。禁用真实模型凭据，使用本地哈希 embedding。部署 Linux prefork worker、beat 和迁移后的 pgvector PostgreSQL，并确认 Celery eager 模式关闭。

1. 固定测试文档、workspace 和预期切片文本，记录空测试库、PostgreSQL/pgvector、RabbitMQ、Celery 版本与 worker pool。上传文件并记录 Document ID、Job UUID、源文件哈希；停止隔离 broker 后再上传第二份。期望 HTTP/持久 Job 可查询，发布失败显示 `retry`，源文件仍可读取；恢复 broker 后在退避到期由 beat 自动完成。
2. 同一 Job UUID 向 `documents` 队列重复投递，完成后核对有效代际切片 `(document_id, ingestion_generation, chunk_index)` 无重复，Job 只完成一次。worker 解析中 `SIGKILL` 子进程，确认租约到期前不错误激活，到期后自动增加 attempt 并完成或明确失败；用可控慢解析分别触发 8/9 分钟限制并记录实际耗时与状态。
3. 在旧任务解析中请求重新入库，在旧任务完成前令新任务运行；另在解析中通过审批删除文档。分别检查旧代际不可激活、有效切片只有新代际，以及删除后 Document/Job/Chunk/向量均不存在、旧任务 URL 为 404。对每步重复查询检索结果，而不只数数据库行。
4. 保持 broker 不可用直至 5 次 attempt 耗尽，核对退避时间、`failed` 及失败告警；恢复 broker 后由同 workspace operator 调用 `reindex/`，核对新 Job 完成且旧索引在切换前仍可检索。记录任务 UUID、request_id、状态时间线、日志错误码、切片数及实际恢复时间。结束后只销毁这套隔离资源。

任一场景出现旧数据复活、重复有效切片、超过 5 次执行、任务永久停留非终态，或任务查询暴露其他 workspace 数据，即视为未通过。真实服务结果仍为空，I-008 保持待验证。
