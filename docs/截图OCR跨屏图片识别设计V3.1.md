# 截图 OCR 跨屏图片识别与保留设计 V3.1

> 2026-10-05。对应 B-048。核心代码已在本地实现并以合成长图/Edge 流程回归；本文的召回率目标、真实用户失败图和复杂网页采集尚未验收，不代表图片识别已达到指标。沿用 [长截图 OCR 转 Markdown 与私有笔记设计 V3.0](长截图OCR转Markdown与私有笔记设计V3.0.md) 的本地 OCR、人工校对和私有/博客图片权限路径。

## 1. 结论

**先修几何与图片候选链路，不把小 Agent 放进默认流程。** 当前 OCR 只返回文字，自动图片候选则只读取网页上已加载的可见 `<img>`。一张图跨两次截图时，虽然现有代码可按同一数字 key 合并两段，但滚动重建 DOM、边缘片段太薄、候选超过每屏 12 个、CSS 背景图或 canvas、以及本地上传图片都可能令 key 或候选缺失。模型无法补回未截到的像素，也不适合决定精确裁剪边界。

推荐两条互补路径：扩展截图优先使用 **DOM 完整矩形 + 实际截图覆盖**；本地上传、CSS/canvas 等无 DOM 元数据的图，使用 **本地像素候选检测**。两条路径在最终长图的统一坐标中去重、显示来源与置信度，用户确认裁剪后才上传。若真实样本证明像素规则的召回率不达标，再评估小型本地视觉检测模型；无需会调用工具的 Agent。通用视觉大模型只可作为明确选择的辅助建议，不能自动保存或发布。

## 2. 当前链路与明确根因

| 环节 | 现有行为 | 漏检场景 |
| --- | --- | --- |
| `shot-content.js::visibleImageCandidates` | 遍历 `document.images`，只留完整加载、可见、裁剪后至少 80×60px 且面积至少 10,000px² 的 `<img>`；记录可见片段，每屏最多 12 个。 | 图片跨屏时某屏仅露出薄条被过滤；CSS 背景、canvas、SVG 绘图和本地文件没有 `<img>` 候选。 |
| `shot-content.js::stableImageKey` | `WeakMap` 按当前 DOM 节点和 `currentSrc` 给数字 key。 | 虚拟列表/懒加载重建节点或换源后，两段同图得到不同 key；同一节点被复用也可能代表另一张图。 |
| `longScreenshot.ts::cropLongShotTiles/mergeCrossTileCandidates` | 把每屏候选裁到选区，再仅按相同 key 合并矩形；无 key 的候选不进入长图合并结果。 | 两段图片即使在像素上连续，只要 key 不同/缺失就显示两个片段或完全不显示。 |
| `ScreenshotOcrDialog.vue` | 用户可点黄色候选框或手工框选，裁剪默认来自压缩后的拼接 JPEG；确认后按目标上传。 | 没候选时不明显；跨屏整图需要自己定位；大图先缩放拼接后再裁剪会损失原像素。 |
| 本地上传 | 只给 OCR 一张图片，没有网页 DOM 元数据。 | 不会自动出现配图候选；仅能手动找图。 |

这些原因可以并存。还须先检查截图源图中是否真的有完整图片：若采集间隔产生缺口、懒加载尚未绘制或遮挡物盖住图片，任何识别方案都不能恢复缺失像素，应提示重截。

## 3. 目标、边界与数据契约

- 用户看到的源图、候选框和最终裁剪必须是同一位置；跨屏单图只出现一张候选。没有把握时显示“可能是同一张图”，允许分开或合并，不静默猜测。
- 文字 OCR 与配图识别分开。图片中的文字可以保留为 OCR 文本，但用户可选择“只保留图片 / 图片和文字都保留”，避免图表标题被重复插入。
- 自动检测只提出候选；用户确认裁剪、插入位置和保存目标后才调用现有私有图片或博客媒体接口。失败保留本地预览与原稿。
- 不新增扩展广域站点权限、不读取图片 URL 作为服务端抓取目标；本地上传图片仍只在浏览器处理，除用户确认的裁剪图外不上传原图。

统一内部类型 `FigureCandidateV2`：`id`、`origin`（`dom`/`pixels`/`manual`）、`rect`（未缩放的逻辑拼图像素坐标）、`fragments`（源 tile、tile 内矩形与页面坐标）、`confidence`、`reasons`、`coverage`（完整/部分/缺口）、`insertAfterBlockId`、`state`。扩展传输仅加入有界的数字几何与会话内匿名 `elementKey`；不传图片源 URL、页面正文或原始 DOM。旧 `screenshot-v1` 记录继续按旧格式读取，缺失新字段时走像素候选和手动框选。

**坐标原则**：使用“框选区域左上角为原点、按截图原始 DPR 计算的逻辑拼图像素”作为唯一内部坐标。每张 tile 保存从屏幕像素到逻辑拼图的变换（滚动位置、选区、裁剪偏移、DPR）。预览 JPEG 即使因 20,000px/30MP 上限缩小，也仅用于显示；最终裁剪从原始 tile 按同一变换重组候选区域，避免再次裁切低分辨率预览。

## 4. 候选生成与跨屏合并

### A. 扩展截图：补足 DOM 几何

1. 每次截图前，对选区内已加载的 `<img>` 同时记录 **完整元素矩形** 与 **本屏可见片段矩形**。元素完整矩形可从 `getBoundingClientRect()` 映射到当前滚动容器坐标；只把已截到的片段标记为覆盖，不能因 DOM 声称图片很长就认为未截部分已保存。
2. 对靠近选区上/下边缘、原图尺寸较大的图片，允许比现有 60px 更薄的可见片段进入候选；仍保留每屏数量/字节上限，并将小图标、导航、固定悬浮图归为低优先级。捕获时记录候选被上限截断的计数，不能把“只发现 12 张”误说成页面只有 12 张。
3. 同一 `elementKey` 且完整矩形、位置和时间一致时合并；key 改变时，可用完整矩形的纵向连续性、横向重合、相邻 tile 的重叠像素指纹辅助匹配。相同图片 URL 或相同像素但出现在页面不同位置时不得合并；节点复用但完整矩形变了也不能仅凭 key 合并。
4. 将合并后的完整矩形裁到**实际已覆盖像素范围**；中间有采集缺口或图片尚未绘制时标“部分图片”，不给出完整候选或让用户补截。

### B. 所有截图：本地像素候选

1. 在浏览器内按原生分辨率扫描图像条带。利用 OCR 文字框、明显的矩形边界、颜色/纹理变化、连续图块和留白提议图片区；跨条带和跨截图用实际像素重叠及坐标连续性合并。检测结果只保存矩形和分数，原像素不离开本地。
2. DOM 候选优先；像素候选与其大范围重叠时合并为一张，留下两种来源供诊断。只有像素证据的候选标“建议区域”，不伪装成确定图片。纯白底线稿、公式、复杂表格和网页截图嵌图可能与正文混淆，始终允许手工重画框。
3. 本地上传长图没有 DOM 路径，直接走像素候选。短截图、跨屏拼图、普通 PNG/JPEG/WebP 都应有一致的候选 UI 和手动兜底。

### C. 合并与排序

候选先统一到逻辑拼图坐标，按来源和覆盖情况打分，再做重叠去重。自动合并需要同时满足：水平位置高度重合、纵向相接或重叠、采集重叠带的像素连续；阈值从标注样本校准，不硬编码为“相邻就合并”。插图顺序按候选中心纵坐标与 OCR 块位置确定，用户可改为前/后一个文字块。整页重复的 logo、导航图和相同素材应保持各自的位置，不因视觉相似而合成一张。

## 5. 校对界面

- 在完整拼图上显示不同来源的候选框：DOM 高把握、像素建议、部分/缺口三种状态；候选列表显示缩略图、所在页位置、来源和“已保留/待确认”。
- 点候选先打开**真正将要上传的裁剪预览**，默认框可拖动调整、放大查看接缝；提供“这不是配图”“合并相邻片段”“分开保留”“重新框选”。没有候选时始终显示“手动框选页面配图”。
- 用户确认后选择放入哪一段文字旁，以及“只图片 / 图片+识别文字”；目标默认沿用当前私有笔记或博客草稿。现有上传、读回验证、取消与失败重试行为保留。
- 显示“本图只捕获部分区域 / 这里可能缺一屏”时不提供一键确认完整图，允许返回扩展补截或只保存已覆盖部分并明确标注。

## 6. 小模型 / Agent 的决定门槛

**首期不加 Agent。** 跨屏同图首先是坐标、DOM 身份和像素连续性问题。LLM 式 Agent 不能精确还原缺失像素，给出的矩形也难保证可裁剪；默认把整张私有截图送给云视觉模型还会改变当前本地处理的隐私和成本。小型本地视觉检测**模型**与 Agent 是两回事：前者可在像素规则召回不足时提议矩形，仍由上述坐标和人工确认约束。

只有在完成真实样本标注后，如果本地上传/CSS/canvas 的像素规则达不到第 7 节门槛，再做模型对照实验。模型必须能本地运行、记录版本与包体/内存/耗时，不自动上传图片或写 Markdown。若将来提供云端视觉“帮我找配图/描述图意”，须由用户单独点击并确认发送的裁剪范围；返回仅为建议，不能自动生成未见内容或执行保存。

## 7. 实施顺序和验收

| 阶段 | 交付 | 验收证据 |
| --- | --- | --- |
| 0：复现和标注 | 收集有权使用的 20 个跨屏页面、10 张本地长图，包含同一图横跨 2–3 屏、虚拟列表重建、懒加载、CSS 背景、canvas、图表/白底线稿、重复 logo、截取缺口；标注真实图片框和可见像素。 | 每个失败例保留源截图、tile 坐标、候选元数据和预期框；诊断记录不含图片内容或完整 URL。 |
| 1：几何修复 | 扩展记录完整/可见矩形，跨屏按 key+几何+重叠像素合并；站内使用统一坐标和原 tile 裁剪。 | `<img>` 跨屏样本召回目标 ≥95%，同图重复候选 ≤2%，裁剪框与标注 IoU ≥0.9；错 key、同 URL 多处、极薄边缘、DPR/内部滚动负例通过。 |
| 2：像素候选 | 本地条带扫描、OCR 框辅助、跨条带合并，接入本地上传和 CSS/canvas 路径；用户可拒绝、合并、重画框。 | 在本地上传/非 `<img>` 的标注样本上召回目标 ≥85%，每页明显误报目标 ≤1；无法达到则如实显示手动路径，进入模型对照实验。 |
| 3：真实验收 | Edge/Chrome 侧载完整采集、校对、私有笔记和博客草稿图片读回；低配设备耗时与内存观测。 | 两个目标均不自动落库/发布；取消、上传失败、重试、跨账号图片 404、拼接缺口、预览与最终裁剪一致；5 位用户能找到并保留跨屏图。 |

上述比例是**拟定验收门槛**，当前未达到也未实测。只有阶段 0 的标注样本和阶段 1 的实际结果出来后，才能判断是否需要引入本地视觉模型。若用户手头有导致漏图的原始长截图或扩展采集会话，优先用它作为第一个回归样本。
