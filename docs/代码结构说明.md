# 代码结构说明

> 生成日期：2026-10-19。覆盖项目内全部自研代码：Django 后端（`backend/`）、Windows 托盘截图工具（`tools/screenshot-tray/`）、浏览器网页剪藏插件（`browser-extension/`）。前端 SPA（`frontend/`，Vue 3 + TypeScript）体量大且另成体系，本表不逐文件展开。

---

## 一、总体架构

项目为 monorepo，Python 代码集中在两处：

| 目录 | 定位 | 技术栈 |
| --- | --- | --- |
| `backend/` | 博客 + 企业知识智能体平台的 Django 后端 | Django + DRF + LangGraph + pgvector/SQLite |
| `tools/screenshot-tray/` | 博客写作配套的 Windows 托盘截图工具 | Python + PyQt6 |
| `browser-extension/` | 浏览器网页剪藏 + 截图 OCR 插件（Chrome MV3） | JavaScript（无构建步骤，源码即产物） |

`backend/` 内部分两块：
- **`backend/apps/agent_api/`**：唯一的核心业务应用（HTTP 层 `views` → 业务层 `services` → 数据层 `models`）；
- **`backend/agent/`**：与 HTTP 无关的 Agent 引擎（Supervisor 多智能体编排、RAG、联网搜索、MCP 工具），被 `views` 和 `services` 调用。

`browser-extension/` 是自研移植的 MarkDownload 风格通用网页剪藏（V0.5.0）：任意网页点扩展图标 → 选「正文 / 我选中的内容 / 整页预览」→ Markdown 预览 → 默认存为**私有笔记**，也可改选**博客草稿**；另有独立的截图功能（当前屏 / 手动区域 / 长页截图，默认仅存图片，可送博客本地 OCR）。权限只有 `activeTab`/`scripting`/`storage`/`offscreen`/`downloads`，不持博客令牌、不上传截图、不自动发布。

## 四、browser-extension/ —— 浏览器网页剪藏 + 截图插件（Chrome MV3）

与后端通过 `externally_connectable`（本地 `127.0.0.1:8001/5173/5174` 三个 origin）+ 一次性交接协议通信；正文经 `chrome.storage.session` 分片传递（2 MiB 上限、64 KiB 分片、SHA-256 校验、5 分钟 TTL、一次性 ack 消费），截图 Blob 只存扩展 IndexedDB（15 分钟 TTL）。

### 4.1 根目录

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | MV3 清单：权限声明、service worker 注册、popup 入口、允许通信的博客 origin 白名单 |
| `background.js` | service worker：剪藏与截图两条交接协议的分块消费中枢（B-045 边界：Blob 只进 IndexedDB、storage.session 只存 nonce/元数据、ack 原子消费） |
| `popup.html` / `popup.css` | 扩展弹窗界面：剪藏范围（正文/选区/整页）、截图入口、保存目标（私有笔记/博客草稿）选择 |
| `popup.js` | 弹窗 DOM 与 chrome.* 适配层；核心剪藏流程在 `shared/clip-flow.js`，只用点击后的临时 activeTab 权限 |
| `offscreen-stitch.html` / `offscreen-stitch.js` | offscreen 私有文档入口（「仅保存图片」长图拼接首选，无感），逻辑在 `shared/local-save-page.js` |
| `stitch-page.html` / `stitch-page.js` / `stitch-page.css` | 标签页兜底入口：offscreen 不可用时由 background 打开，拼接逻辑同上 |
| `README.md` | 插件说明：权限边界、侧载方法、使用步骤、截图/OCR 链路、常见错误与测试命令 |

### 4.2 shared/ —— 共享逻辑（纯函数可 Node 单测）

| 文件 | 职责 |
| --- | --- |
| `shared/protocol.js` | 剪藏一次性交接协议纯函数：记录构造、UTF-8 分片、SHA-256、URL 清洗与访问校验；只传正文+标题+用户笔记，绝不承载博客令牌/Cookie |
| `shared/clip-flow.js` | 剪藏流程编排：popup 侧准备 + worker 侧分块消费；DOM/BOM 通过 adapter 注入，Node 可驱动完整流程 |
| `shared/extract-core.js` | 通用正文抽取 + DOM 转 Markdown（类 Readability 评分选正文容器 + 类 Turndown 规则转换，MarkDownload 移植，无第三方依赖）；页面内执行的经典脚本 |
| `shared/extract.js` | extract-core 的 ESM 门面，供 Node 测试与扩展弹窗 import |
| `shared/shot-protocol.js` | 截图交接协议纯函数（screenshot-v1）：tile 元数据、分块、访问/重放校验；Blob 只存 IndexedDB，storage.session 只存元数据 |
| `shared/screenshot-flow.js` | 截图流程编排：会话暂存（IndexedDB adapter）+ worker 侧分块消费 |
| `shared/shot-content.js` | 截图采集 content script（chrome.scripting 按需注入）：几何测量、滚动与恢复、Shadow DOM 覆盖层 UI；不读页面正文/Cookie |
| `shared/longshot-stitch.js` | 长截图拼接几何纯函数（与博客页同一套数学）：拼接计划计算 + tile 拼接，canvas 由 adapter 注入，不依赖 DOM |
| `shared/local-save-page.js` | 「仅保存图片」页面侧执行：读截图会话 → IndexedDB 取 tile → canvas 拼长图 → 存下载目录 → 回传 worker；offscreen 与标签页两个入口共用 |

### 4.3 tests/ —— Node 单元测试

## 五、工作顺序

### 5.1 后端启动顺序（服务起来经历了什么）

```
manage.py runserver
  └─ config/settings.py          读 .env，决定本地模式/数据库/安全档位
      └─ config/__init__.py      注册 celery_app（Celery 就绪）
      └─ 各 app 的 apps.py       core → users → agent_api 依次加载
      └─ models/__init__.py      21 张业务表元数据注册（migrations 负责 schema）
  └─ config/urls.py              根路由
      ├─ apps/core/urls.py       /api/health/ 健康检查（判断后端活没活就看它）
      └─ agent_api/urls.py       按领域分发到 api_urls/{agent,auth,blog,governance,knowledge,projects}
          └─ 各 api_urls/*.py    把 URL 映射到 views/
```

### 5.2 一次 HTTP 请求的分层顺序

```
api_urls/*.py（URL 路由）
  → views/*.py          HTTP 层：鉴权、参数校验、调用 services、组装响应
    → serializers/*.py  模型 ↔ JSON 的出入参转换
    → services/*.py     业务逻辑（blog、knowledge、rag、evaluation …）
      → models/*.py     ORM 读写数据库
    → agent/*           涉及 Agent 能力时进入引擎层
  → exceptions.py        任一层抛异常，统一转成 {detail, code} 错误格式
```

### 5.3 聊天/Agent 链路顺序（核心运行时流程）

```
前端发消息
  → views/chat.py               鉴权 + 建会话/消息
    → agent/security.py         JWT 身份、角色、工作区隔离、敏感信息脱敏
    → agent/multi_agent.py      MultiAgentSupervisor 编排入口
      → agent/supervisor_routing.py   纯函数判定路由：安全优先级 + 关键词
      → agent/specialized_agents.py   执行对应专用 Agent（博客/SQL/MCP/写作/联网）
        ├─ 博客/RAG 路线：
        │   agent/query_rewriting.py    指代消解，改写查询（用原始问题抽实体）
        │   → agent/rag_tools.py        管道函数
        │     → services/rag/search.py  向量召回 → 混合打分 → 重排 → 多样性配额
        │       → services/vector_store.py  pgvector / SQLite 兜底
        │     → agent/agent_text.py     意图识别、机构抽取、本地兜底回答
        │   → agent/rag_prompts.py      提示词拼装
        ├─ 联网路线：agent/web_search.py（多 provider 降级）
        │   → agent/web_search_parsers.py 解析结果
        │   → agent/internet_answer.py    带来源标注合成答案
        └─ 工具路线：agent/tools.py（计算器/文件搜索）、agent/mcp_tools.py（MCP 调用，经 governance 审批）
      → agent/simple_agent.py   Agentic RAG 状态图：判断是否需要检索/改写，循环至可作答
    → agent/llm_support.py      统一 LLM 构造与 token 统计（贯穿全程）
  → SSE 流式回传前端
```

### 5.4 知识入库链路顺序（RAG 写入侧）

```
views/knowledge.py（文档上传）
  → services/ingestion_jobs.py    写事务性 outbox，登记入库作业

      → services/rag/ingest.py    抽取文本 → 切分
```

### 5.5 截图工具启动顺序

```
run.bat → main.py
  1. SingleInstance.acquire()      抢互斥锁，双开静默退出（core/single_instance）
```

### 5.6 浏览器插件工作顺序

**加载顺序**（浏览器加载扩展时）：

```
manifest.json 读入
  ├─ 注册 background.js（module 型 service worker，事件驱动、按需唤醒）
  │    └─ import 协议与流程模块：protocol.js / shot-protocol.js
  │                → clip-flow.js / screenshot-flow.js（交接消费中枢就绪）
  ├─ 注册 popup 入口 popup.html → popup.js（点击图标才实例化）
  └─ icons / externally_connectable 白名单生效
```

**网页剪藏流程**（v2 通用剪藏）：

```
用户点扩展图标 → popup.js
  → 用户选范围（正文/选区/整页）→ 点「读取并预览」
  → 临时注入抽取器 → extract-core.js   类 Readability 评分选正文 + 类 Turndown 转 Markdown
  → clip-flow.js（popup 侧）           构造记录：标题+正文+用户笔记+目标，sanitizeWebSourceUrl 清洗
  → 分片写入 chrome.storage.session    64 KiB 分片 + SHA-256，随机 nonce 存 URL
  → 用户点「送到博客」→ 打开博客页
  → 博客前端向 background.js 发 get-meta / get-chunk
  → background.js（clip-flow worker 侧）validateWebRecordAccess（校验 origin/tab/TTL）
  → 一次性 ack 消费，分片回传 → 站内 /imports/html/preview 重新安全校验
  → 用户在预览里确认 → 存私有笔记（默认）或博客草稿
```

**截图流程**（screenshot-v1，B-045）：

```
用户在 popup 选「当前屏 / 手动区域 / 长页截图」
  → popup 请求 activeTab → chrome.scripting 注入 shot-content.js
  → shot-content.js     测量几何 → 画 Shadow DOM 覆盖层 → 用户框选矩形
  → 长页模式：用户在框内滚动，content script 停顿时采集整视口 tile
  → tile Blob 存扩展 IndexedDB（15 分钟 TTL），storage.session 只存元数据+nonce
  → 用户点小窗「完成」→ 按所选去向收尾：
      ├─ 仅保存图片（默认）：background 打开 offscreen-stitch（失败兜底 stitch-page）
      │    → local-save-page.js  读会话 → longshot-stitch.js 拼长图 → downloads 存盘 → 回传 ack 清理
      └─ 送到博客识别：与剪藏同一条分片交接协议 → 博客页先拼最终长图 → 本地 OCR 一次
           → 左图右 Markdown 校对 → 送未保存私有笔记草稿（或博客草稿）
```

**关键顺序约束**：交接消费是一次性的（ack 原子消费 + 清理），错 origin/错 tab/过期/重放一律不 ACK；回传消息只能「页面 → worker」（worker 反向先发会因页面未执行而丢消息）；「完成」之前不产生任何去向，截图不上传任何像素。

## 六、依赖方向总览

```
api_urls ──→ views ──→ services ──→ models
                │           │
                ▼           ▼
              agent（引擎层：multi_agent / simple_agent / rag / web_search / tools）
                            │
                            ▼
                       llm_support（最底层）
```

- `views` 不直接碰 ORM 以外的业务细节，业务全在 `services`；
- `agent/` 不 import DRF，可脱离 HTTP 单测；
- `services/rag/*` 是 RAG 唯一权威实现，`agent_api/rag.py` 与 `services/llm_support.py` 只是兼容旧路径的转发层；
- 截图工具与后端仅通过 HTTP API（`blog_api_client`）和本地 handoff 端点交互，无共享代码；
- 浏览器插件与站点的接触面只有两处：`externally_connectable` 白名单 origin + 前端 `/imports/html/preview` 安全校验；`shared/*` 内部又分两层——协议/拼接纯函数（protocol、shot-protocol、longshot-stitch）不依赖 DOM、可 Node 单测，流程层（clip-flow、screenshot-flow、local-save-page）通过 adapter 注入 chrome API。
