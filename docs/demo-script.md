# 项目演示与面试脚本（I-023）

定位：**个人知识管理与内容生产平台**。以下是待现场执行的演示步骤，不表示已录制或完成真实用户验收。使用隔离环境、合成资料和已由授权流程配置的 operator/admin 测试账号；公开注册只创建 visitor。不要展示私有用户资料、密钥，也不要直接发布真实内容。个人设计/实现分工须由本人补充，见[简历要点](resume.md)。

## 面试说明：一个典型难题

**问题：**初始方案把混合检索、历史改写和重排叠加起来，但没有证据证明复杂度换来了真实收益。

**解决过程：**先冻结 28 条合成切片、38 条暂定来源映射题（24 调参、14 独立验证），共享语料与 Top-K，逐项只增加向量、确定性历史拼接及**规则重排**；记录逐题 Recall@5、MRR@10、排序延迟和失败案例。`q29` 在混合、历史拼接及重排不同权重下仍漏召。14 条独立验证题里有暂定来源的 10 题，关键词命中 **10/10**，当前混合 **8/10**，历史拼接与规则重排 **9/10**；这些是本地哈希/未复核映射的诊断结果，不能宣称真实检索优劣。真实 embedding 请求遇到 `APIConnectionError`，答案依据性和完整请求成本未测，因此保留现有生产权重，等待人工标注和真实服务重测。来源：[I-001 评测报告与口径](I-001-RAG检索消融评测.md)、[逐题机器结果](evaluation/i001-local-hash-v1.json)。

**架构取舍：**规则 Supervisor 负责选择路径和保持授权边界；RAG 小图负责有界查询分析、检索、相关性判断、最多一次改写和生成，图状态只在单次调用内存中存在。运行记录和文章审批是业务持久化，不是图节点恢复。保留小图是兼容现有 SSE/状态接口的决定，尚无同条件函数/图效果或性能优势证据。来源：[I-007 ADR](I-007-LangGraph工作流决策.md)、[I-021 架构](I-021-当前架构与技术取舍.md)、[I-022 评估](I-022-草稿审批与恢复评估.md)。

**后续验证：**请资料作者审核问题与可接受来源，在隔离 PostgreSQL/pgvector、真实 embedding 和真实模型条件下复跑；再对照人工审核的答案依据性、完整请求成本及 HTTP P50/P95，决定是否调权重或简化图。当前报告不支持任何“提升 X%”说法。
