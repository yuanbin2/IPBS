## 当前问题与目标

阅读页已可在正文位置切换为 `Vditor` 的 `wysiwyg` 编辑器，旧独立写作入口仍供新建文章使用。此前 `BlogArticleDetailView.put` 修改已发布文章会让公开链接消失，B-025A 已改为待审修订，待真实 PostgreSQL 升迁验收。博客列表已有分页、组合筛选与 URL 状态保留，仍缺真库性能和非作者找文任务证据。原“我的笔记”已更名“我的文章”，独立私有笔记可在阅读页旁记录与检索；真实用户任务仍待完成。

笔记侧边栏现可手动勾选最多 10 条笔记，并在点击“汇总已选笔记”时调用现有写作助手。服务端只读取当前登录者同一工作空间的笔记，汇总后显示实际纳入来源、截断和模型信息；生成内容可直接可视化修改，亦可复制或另存为私有笔记。每账号每小时最多 10 次模型调用，真实共享 Redis 和模型成本/质量仍待验收。

目标是作者在自己的文章中按“编辑”即可在当前阅读位置改写格式化正文，读者在审核期间继续看到上一个已发布版本；通过可检索列表快速找到文章；阅读时能留下私有笔记，并由现有写作助手 API 按需汇总笔记。所有 AI 输出先给用户审阅，不自动改写文章或发布。

## 关键交互与边界

- **编辑权**：普通作者只能改自己的文章；管理员可处理审核。前端按钮只是提示，API 必须独立校验角色、作者和 workspace。已发布文章在审批前保持公开快照；访客绝不能看到待审修订。
- **自动保存**：本机缓存仍按账号、workspace、文章 ID 隔离；服务器保存要有版本令牌，两个标签页冲突时暂停覆盖并让用户选择。切换阅读与编辑不能重建空编辑器覆盖未保存内容。
- **笔记隐私**：私有笔记不经公开博客接口、公开搜索、推荐或博客助手返回。仅在用户点击汇总时将所选笔记发给现有写作模型；界面展示来源和截断，服务端不接受客户端代传正文。模型错误时保留原笔记且提供重试。模型服务商会接收所选内容，正式使用前须确认其数据处理条件与成本。
- **指标**：记录保存失败率、冲突率、编辑任务完成时间、找文章成功率、搜索零结果率；只记录聚合指标，不把私有笔记正文写入分析日志。指标先建立基线，再定正式门槛。

## 推进规则

一次只实施上表一个最小阶段。每阶段先补失败用例与迁移方案，再改后端权限/数据，最后接前端；运行受影响专项与默认/强安全后端、真实浏览器主路径、前端类型/构建和迁移检查。发现回归先修复，不把下一阶段功能叠上去。桌面端口保持 5174，不触碰 `app-desktop/.edge-profile`；未经授权不部署 Railway、不购买资源、不批量调用付费模型。

**编辑排版资源自托管与工具栏补齐（2026-10-06）**：排查写作排版能力时发现，Vditor 的核心解析器 lute、KaTeX 公式、mermaid 流程图、代码高亮样式全部在运行时从 unpkg CDN 按需拉取（默认 `cdn = https://unpkg.com/vditor@版本`）；CDN 慢或不可达时编辑器初始化缓慢、公式/流程图/高亮直接失效——占位文案里承诺的"公式、流程图"实际不可靠。文章阅读页与 OCR 校对预览用的 md-editor-v3 同样默认从 jsdelivr 拉取 katex/mermaid。现按 OCR 资产的同源策略修复：新增 `frontend/scripts/sync-editor-assets.mjs`（dev/build 前自动执行），把 lute、katex（含字体与 mhchem）、mermaid、flowchart、highlight.js（含全部主题）、icons、i18n、content-theme、images 复制到 `public/vendor/vditor/`（约 12MB，含清单）；`VditorEditor` 设置 `cdn: "/vendor/vditor"`，md-editor-v3 在 `main.ts` 经 `configureMarkdownExtensions()` 指向同一份 katex/mermaid。排除 mathjax/graphviz/plantuml/echarts/markmap 等未启用引擎，启用时需在脚本补录。Django 单端口与 nginx 均为 `/vendor/` 注册静态路由（缺失 404，不落入 SPA 兜底），并有回环测试。工具栏补齐 `outdent`/`indent`（缩进）、`insert-before`/`insert-after`（行首行尾插入）、`format`（一键整理 Markdown）和一个声明式"行内公式"按钮（`$` 前后缀，选中文字直接包裹）。验证：`npm run build:check`、前端单测、Django 资产路由测试、隔离 Edge OCR 专项与 clip-handoff 大部分用例通过；clip-handoff"未登录访客"用例连接硬编码的 5188 端口（该端口无服务、改动前即失败），与本次无关。公式/流程图在真实长文中的渲染效果仍需人工验收。

**写作台工具栏吸附修复（2026-10-06）**：用户反馈编写时下滑后工具栏（Vditor toolbar）看不见。排查：VditorEditor 已配置 `toolbarConfig.pin: true`（即 `position: sticky; top: 0`），但 Vditor 自身样式给 `.vditor` 根元素加了 `overflow: hidden`——sticky 的约束盒是最近的 overflow 容器，被限制在这个从不滚动的编辑器盒子里，吸附永远不会触发。修复：VditorEditor 组件根（即 `.vditor` 元素）放开为 `overflow: visible`，下侧圆角改由 `.vditor-content` 裁剪，工具栏显式 `position: sticky; top: 0; z-index: 20`；编辑器最小高度 480px 兜底。该修复对写作台、文章行内编辑、私有笔记三处 VditorEditor 同时生效。新增隔离 Edge 回归用例 `writer-toolbar-sticky.spec.ts`（编辑器顶部滚出视口后断言工具栏 top≈0 且仍在编辑器范围内）通过；`npm run build:check`、前端单测 58/58、blog-drafts 12/13（:71 为既有样本重复断言缺陷）。

**博客首页辅助栏精简（2026-10-06）**：用户反馈右侧可隐藏的辅助栏（BlogSidebar）冗余且过长。精简三处：其一，删除置顶的“知识索引”统计盒——文章/分类/标签三个数字与主栏 hero（library-hero-stats）完全重复；其二，专题标签按文章数降序排序后默认只展示前 12 个，底部提供“展开其余 N 个标签/收起”切换；其三，时间归档默认只展示最近 6 期（后端按 -published_at 生成、组序即最新在前），提供“展开更早的 N 期/收起”切换。文章分类与作者简介保留不动；共享样式（style.css 的 side-box 系列）未动，知识库侧栏不受影响。`npm run build:check`、前端单测通过；blog-drafts 的 20 样本用例存在改动前即有的严格模式断言缺陷（两个样本都含 `console.log(answer)`，定位歧义），与本次无关。
