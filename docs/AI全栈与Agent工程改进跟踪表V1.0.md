## 维护规则

- `I-xxx` 是稳定编号，不随排序变化。后续新增编号递增并插入所属表顶部；执行顺序由优先级与依赖决定。
- P0：已证实的安全、数据丢失或发布阻断问题；P1：核心正确性、可靠性或可信评测；P2：维护性、体验和性能优化；P3：条件性架构增强与作品整理。新发现严重问题可升级，并写明依据。
- 状态：`待核查`（尚未确认缺口）、`代码确认`（静态证据，不等于运行复现）、`待设计`（需先明确方案/门槛）、`待开发`、`开发中`、`待验证`、`已完成`、`已延期`、`已取消`。
- “当前依据”不能作为完成证据。只有实现、必要测试、规定的环境验收与记录齐全，才标记 `已完成`；无法做的实机/模型/生产验收必须保持未完成或拆为独立待办。
- 与 [缺陷跟踪表](缺陷跟踪表V2.0.md) 重叠时，本表记录改进路线，原 B 编号保留为具体缺陷的状态来源；互相链接并同步必要状态，不能重复计算完成量。
- 每次只领取一个闭环或少量同域任务。开始前核查依赖和用户已有改动，完成后更新本表及下方实施记录。不因台账存在而自动安装服务、升级依赖、访问外部账号或部署生产。
- 所有指标必须注明数据集、模型/提示词版本、运行环境、样本量与统计口径。验收前冻结目标，不使用虚构提升比例，也不把 mock、SQLite 或合成数据结果当作真实模型、PostgreSQL 或实机结果。

### I-005 模型用量与成本口径（2026-10-22）

聊天 `AgentRun.model_calls` 每项只保存 `run_id`、调用 ID、用途、模型名、耗时毫秒、状态、错误类型、显式重试序号、三类 token 用量及可计价金额；不保存模型输入、输出或异常正文。`model_accounting` 汇总所有已触发回调的调用。服务商未给 usage 时 token 为 `null`，汇总相应维度也为 `null`，`unknown_usage_calls` 计数；没有发生模型调用时才是已知的 0。失败调用若无 usage，其潜在 token 与成本仍列入未知部分。若旁路模型给出了旧 token 字段但未触发回调，记录 `unobserved_model_calls=true` 并把成本列为未知，不虚报完整计价。相同 run_id 的重复请求复用记录，不重新调用模型或累加用量。

`AGENT_MODEL_PRICES_JSON` 是显式价格表，例如 `{"version":"provider-YYYY-MM-DD","currency":"USD","units_per_token_price":1000000,"models":{"exact-model-name":{"input":"1.00","output":"2.00"}}}`。`input` 和 `output` 均为每 100 万 token 单价；代码使用十进制计算。未配置或未列入模型的调用保留 `known_cost` 已知小计，同时增加 `unknown_cost_calls`，`complete_cost=false`；不把未知部分写成零元。价格版本随每次 run 固化，不能将估计值称为真实账单。SDK 隐藏的自动重试已在共用 ChatOpenAI 构造器和写作助手中关闭；若调用方显式重试，每次回调分别记录，失败而无 usage 的尝试仍显示未知。独立访客博客及博客写作接口没有 AgentRun，目前不提供持久的跨调用 run 汇总，属于本项未验收范围。
