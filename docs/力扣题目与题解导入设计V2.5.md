## 1. 产品目标与决定

作者在“写博客”中粘贴一道力扣题目的链接，系统创建带来源链接的**可编辑刷题草稿**，预先安排“我的题意理解、思路、代码、复杂度、易错点、参考资料”等章节。作者可以贴入自己写的代码、笔记和题解，逐段修改后走现有发布审核。题目链接能直接跳回力扣原页，读者也能核对来源。

用户希望进一步一键取得原题描述和现成题解。技术上可以用页面抓取或站内未公开接口实现，但这不应作为默认实现：截至本文编写时核对的[力扣中国服务条款](https://leetcode.cn/document/terms/)第 3.1.6、5.2 节要求对复制、改编、传播等行为取得相应书面授权；[LeetCode 国际站条款](https://leetcode.com/terms/)明确限制 crawling/scraping，题目和题解也属于受保护内容。[力扣原创保护说明](https://support.leetcode.cn/hc/kb/article/1583409/)特别提醒题解引用需注明出处并反对搬运。因此**“附上来源链接”不等于获得完整转载许可**。这是产品约束，不由用户点击一个“我同意”复选框自动消除。

本设计采用两条路径：

| 路径 | 默认是否开放 | 导入内容 | 发布规则 |
| --- | --- | --- | --- |
| 题目链接建卡＋本人创作 | 是 | 规范化题目 URL、用户填写的题名/编号、本人题意理解、代码和解题笔记；系统给章节模板，不复制力扣题面或他人题解。 | 保留原题链接，按现有博客审核发布；审核人检查署名、内容来源和竞赛状态。 |
| 已获授权的完整内容导入 | 否，需明确授权及可用的官方/许可数据入口后单独开启 | 授权范围内的题面、示例或指定题解，逐项列出来源、作者、授权范围和导入时间；用户可取消任意部分。 | 只有授权覆盖公开转载及必要的图片、代码等资源时才允许提交公开审核；否则只保留来源链接。 |

“我的题解”也要区分用户自己写的草稿、已在力扣发布的作品和从别人页面复制的内容；如果作品曾受平台的投稿/会员协议约束，仍需核对可再次发布的权利。竞赛进行中不导入或辅助传播题解；遵循[力扣竞赛规则](https://support.leetcode.cn/hc/search/link/id/1278066/search_id/100296383/)对场外辅助工具及赛中答案传播的限制。

## 2. 与现有 Blog/HTML 导入的关系

- 前端复用 `BlogWriter.vue` 的“导入”入口、覆盖旧草稿前确认、`ParsedMarkdown` 映射、本地草稿缓存和多标签冲突提示；生成的正文仍是 Markdown，交给现有 Vditor `wysiwyg`，不引入第二套编辑器或“编辑源码”流程。
- 后端复用 Django DRF 的认证、限流和审核链路。新文章继续使用 `BlogArticle` 的 `DRAFT` 状态和 `ApprovalRequest`，不会因导入而直接发布或写入公开知识索引。已有文章原位编辑暂不显示整篇导入按钮，以免误覆盖正文。
- [HTML 导入设计 V2.4](HTML导入Markdown博客设计V2.4.md)的纯转换器只处理用户提供的 HTML 文件。它既不是力扣授权数据接口，也不应被“URL → 自动下载力扣 HTML → 转 Markdown”复用成绕开本设计边界的抓取器。
- 图片遵守已有 `blog_media` 的 MIME、大小、真实解码、读回和持久化规则。链接建卡阶段不下载力扣图片；获授权的资源才进入独立、可追溯的资源导入流程，不把外链伪装成本地图片。

## 3. 作者和读者体验

### 3.1 默认流程：链接建卡

1. 作者选择“写博客 → 导入 → 力扣题目”，粘贴 `leetcode.cn/problems/{slug}/` 或 `leetcode.com/problems/{slug}/`。可选填题号、中文题名、难度、标签；这些字段由用户确认，不把 URL slug 猜出的标题当已核实元数据。
2. 弹窗先显示域名、规范化后的原题链接、来源类型和待填字段。只解析 URL，不向力扣或第三方服务发网络请求，也不索要力扣账号密码、Cookie、Premium Token 或浏览器扩展权限。
3. 作者选择“空白解题模板”或“从我已有的 Markdown/HTML 导入本人内容”。前者生成可编辑章节；后者调用现有本地文件转换/预览，清楚显示将覆盖哪些草稿字段。用户可粘贴自己的代码，保留语言标记与格式。
4. 预览左右对照：左侧为来源卡、用户填写的元数据和章节选择，右侧为最终 Markdown 排版。任何字段均可修改；取消时旧草稿完全不变。确认后导入当前草稿，保留之前的缓存/冲突机制。
5. 文章开头或末尾有固定“原题链接”卡；公开阅读时点击前往力扣。引用他人题解只存题解标题、作者和链接，由作者在“参考资料”中说明借鉴点，不整篇复制。

建议模板：

````md

> 题号 / 难度 / 标签：待填写

## 我的题意理解

用自己的话概括输入、输出和关键约束。

````

### 3.2 获授权后的扩展流程

只有项目持有人记录了授权范围、来源、有效期、允许的获取方式和公开展示范围，且有可依赖的官方/许可数据接口时，才开启“获取题面/题解”按钮。预览中将**题面、示例、约束、题解、代码、图片**作为分开的可选块，分别标注作者与授权范围；不能把“官方题解”“社区作者题解”和“我的笔记”混成一个无署名正文。正文变更差异在确认前可见。若授权、接口或资源校验失败，退回链接建卡，不把错误页、登录页或缺图内容当成成功题目。

题解导入默认只允许用户本人可证明有再次使用权的作品或逐篇取得许可的作品。第三方题解的普通模式始终是**链接＋摘要由作者自行撰写**。不接入付费题、登录态内容和竞赛中的内容；不通过内部 GraphQL、伪装浏览器、会话 Cookie、第三方镜像、反爬绕行来替代授权。

## 4. 技术接口与数据设计

### 4.1 第一阶段接口

`POST /api/agent/blog/imports/leetcode/link-preview/`，真实登录态，JSON 请求：`{ "url": "https://leetcode.cn/problems/two-sum/", "title": "两数之和", "frontend_id": "1", "template": "solution-note" }`。服务端只解析字符串并返回 `{ provider, canonical_url, problem_slug, user_entered_metadata, content_markdown, warnings, converter_version }`，不访问目标站、不落库、不调用模型。URL 仅允许上述两个精确域名及 `/problems/{slug}/` 路径；去掉跟踪参数、锚点与无关路径，不接受子域、IP、短链、重定向和凭据。输入限长 2 KiB，生成正文限长，按用户限流。前端拿预览结果后仍须用户确认才能应用草稿。

这一步也可以在前端纯解析，但后端预览契约更容易统一桌面/浏览器行为、测试 URL 安全规则，并为将来授权适配器留一个版本化边界。接口名含 `link-preview`，避免误解为已经获取原站正文。

### 4.2 授权适配器接口（第二阶段，默认关闭）

定义 `ProblemSourceAdapter`：`resolve_problem(canonical_url) -> LicensedProblem` 与 `resolve_solution(solution_id) -> LicensedSolution`。返回数据必须包含 `source_url`、`source_author`、`content_kind`、`license_id`、`fetched_at`、`sha256`、`blocks`、`asset_manifest` 和明确的 `can_republish`；缺任一关键权限字段即拒绝公开复制。适配器只面向经审核的许可入口，具体 API 与请求频率要按将来取得的许可文件落地，**当前不假定有稳定的公开力扣 API**。预览服务与持久化服务分离，预览失败无文章、附件或审核记录副作用。

新增 `BlogImportSource` 表仅在第二阶段需要，字段建议：`article_id`、`workspace_key`、`provider`、`problem_slug`、`canonical_url`、`content_kind`（question/solution/asset）、`source_author`、`permission_reference`、`license_scope`、`fetched_at`、`content_sha256`、`converter_version`、`created_by_id`、时间戳；索引 `(workspace_key, provider, problem_slug)` 和 `(article_id, content_kind)`。授权证明单独受管理员权限保护，不放公开序列化器或日志。文章正文仍只在 `BlogArticle.content` 存 Markdown；预览原始 HTML/JSON 不入库。作者后续编辑不触发自动同步，避免覆盖自己的内容；需要更新时显示“来源新版与当前草稿差异”，用户逐块选择。

## 5. 安全、权限、版权和失败处理

- 第一阶段没有服务器出站访问，因此不存在“用户提交任意 URL 让服务器请求”的 SSRF 面。第二阶段仍必须固定许可域名/端点、验证全部 DNS 地址与 TLS、不跟随任意重定向、不转发浏览器 Cookie，并设置单次大小、图片数量、超时、缓存和用户配额；沿用现有远程图片防护，但不能仅靠 SSRF 防护认定内容有使用许可。
- 题面、题解、代码和图片分别判断授权，保留原作者、题号和精确来源链接。来源链接必须可在审核时查看；用户声明、标注出处或私人使用意图都不自动证明拥有公开转载权。管理员在审核时可退回缺来源/缺许可的导入稿。
- 严禁自动批量导入、按题号遍历、私有接口查询、Premium 内容提取、自动同步全站和把抓取结果加入 RAG/模型训练。作者提供的代码若包含密钥或个人信息，沿用现有敏感信息检查。
- Markdown 中任何原站 HTML、脚本、事件属性和危险链接必须经 HTML 导入相同的双层清理与阅读端过滤。图片存储失败则不改草稿；保存了部分资源但后续失败时需清理未引用临时对象，不能长期积累孤儿文件。
- 链接不匹配：给出可更正的输入错误；题号/名称未知：仍允许创建“待填写”模板；草稿已有内容：字段级差异与覆盖确认；授权失效或许可接口不可用：只提供链接建卡，不静默退化为抓取。

## 7. 暂不启动完整内容获取的条件

下一步可以直接实施 B-041A，不需要购买服务。要做“一键获取完整题目描述和题解并发布”之前，需先取得权利人对**访问方式、复制、改编、存储、图片与公开再发布**的明确许可，并确认具体官方/许可接口。若只想减少重复书写而暂时没有许可，链接建卡＋本人解题模板已经能覆盖主要写作步骤，且能作为面试作品讲清楚来源治理、权限、Markdown 转换和审核边界。

## 8. B-041A/B 实现记录（2026-10-03）

### 8.1 实际落地范围

**后端（B-041A）**

- 新增纯函数服务 `backend/apps/agent_api/services/leetcode_link_import.py`（`converter_version=leetcode-link-v1`）：只做字符串解析与模板生成，模块不导入任何网络库；`resolve_problem_url()` 仅接受精确域名 `leetcode.cn` / `leetcode.com` 与 `/problems/{slug}/` 单段路径，统一为 HTTPS 规范 URL、去掉 query/fragment，拒绝子域、IP/伪装 host、凭据、显式端口、`%` 编码、反斜杠、控制字符（含 `\x1c`-\x1f 这类会被 `str.strip()` 剥离的字符，检查先于 strip）、空/大写/非法 slug、多段路径与超过 2 KiB 输入。
- `build_link_preview()` 返回 `{provider, canonical_url, problem_slug, user_entered_metadata, content_markdown, warnings, converter_version}`。题名/题号/难度/标签均为用户输入；元数据先经 `_clean_inline_text()`/`_clean_tags()` 清洗：markdown 结构字符（`[ ] ! # * _ ~ | \` < > \ " 及控制符）一律替换为空格，从源头杜绝额外链接/图片/标题/脚本注入（用户文本仅以纯文本形态保留在链接文字中）；难度为白名单枚举；代码语言限 `[a-zA-Z0-9_+.#-]{1,20}` 且仅作为围栏信息串。模板含“原题链接”引用卡与 我的题意理解/我的思路/代码实现/复杂度分析/易错点与复盘/参考资料 六章节。
- 新增 `POST /api/agent/blog/imports/leetcode/link-preview/`（`BlogLeetcodeLinkPreviewView`，路由加入 `api_urls/blog.py`）：真实 JWT 身份（开发角色头/旧 session Cookie 不算），沿用统一错误结构，Redis 缓存限流 60 次/小时，请求体仅解析字段——不落库、不调用模型、无出站请求。无新表、无迁移。

**前端（B-041A + B-041B）**

- 新增 `LeetcodeImportDialog.vue`，在 `BlogWriter.vue` 工具栏以“导入力扣题目”入口打开（`editingArticle` 时隐藏，仅新建草稿可用）。弹窗填写 URL 与题名/题号/难度/标签/代码语言，调用预览接口后显示来源卡（provider、规范来源链接、逐字段“待确认”徽标、警告说明）与 `MdPreview`（经 xss 清洗）安全排版预览。
- 应用走 `BlogWriter` 既有导入链路：草稿非空先弹覆盖确认（取消则草稿一字不动），成功前不写草稿、不保存、不发布；导入后正文仍是 Markdown，继续用现有 Vditor `wysiwyg` 编辑，本地草稿缓存、多标签冲突、刷新恢复、发布审核全部沿用。
- **B-041B“附上我的笔记”**：同一弹窗内支持追加本人 `.md/.markdown/.txt`（前端 `parseMarkdownFile` 解析，去 frontmatter 与首个 H1 标题防重复）与 `.html/.htm`（复用既有 `imports/html/preview` 纯转换 API，未复制解析器）。HTML 区块**默认全不选**，由作者逐块勾选；每份附件须填写“来源标注”（默认“本人笔记”），以引用行随内容写入所选章节（我的思路/代码实现/易错点与复盘/参考资料/我的题意理解/复杂度分析），不覆盖模板结构、不重复标题。图片遵守 B-040 规则：本地图片按路径/唯一文件名匹配后经既有上传接口入库；远程图片经既有 fetch 端点本地化（operator 权限），任一失败则草稿保持原样；未匹配本地图片以文字提示保留，不把外链伪装成本地文件。图片匹配辅助函数提取为 `utils/imageFileMatching.ts` 供两个导入弹窗共用。
