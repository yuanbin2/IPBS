# HTML 导入 Markdown 博客设计 V2.4

> 2026-10-02 设计完成，**尚未实现/测试**，对应缺陷表 B-040。目标是把用户从浏览器保存的网页 HTML 转成可在现有 Vditor 中直接编辑的 Markdown 草稿。本文数字均为拟定验收门槛，不是实测结果。

## 1. 目标、输入与明确边界

用户在“我的文章 → 新建”选择 `.html`/`.htm`，看到提取出的标题、正文、图片/链接警告和 Markdown 排版预览，确认后填入**当前写作草稿**；用户还能继续所见即所得编辑，决定保存、下载 `.md` 或按现有流程提交审核。导入预览绝不自动发布、替换现有草稿或送入公开知识索引。

首期支持静态 HTML 文件，包括“仅 HTML”的浏览器保存结果和文章主体在 `<article>`/`<main>` 中的常见页面。动态 JS 执行后才出现的正文、登录后才能访问的内容、原站 CSS 像素级还原、脚本交互、完整网站镜像及网页地址抓取不属于首期。若文件只有 JS 数据壳，提示用户改用浏览器的“另存为完整网页”或复制正文，不输出空白“成功”文章。完整网页伴随的本地图片目录需要第二阶段的受限资源包；单个 HTML 文件本身无法让服务端读取用户电脑上相邻目录。

转换是**确定性的内容迁移**，不调用博客写作模型，不让模型改写原文。Markdown 是站内唯一文章正文格式，原始 HTML 不作为可公开访问的附件保存。

## 2. 现有系统接点与技术选择

| 问题 | 选择与原因 | 暂不选的方案及触发重评条件 |
| --- | --- | --- |
| 转换放哪里 | 新增 Django DRF `multipart/form-data` **只预览**接口；服务端用 Python 解析字节，不运行浏览器/JS、不发起网络请求。前端沿用 `requestJson` 与已修复的 FormData 边界。上传只为转换，正常完成或失败后不留原文件。 | 浏览器 `DOMParser + Readability + Turndown` 可避免上传原文件，但在本项目已有 Django 上传链路之外要管理恶意资源加载、浏览器差异、两个渲染器与离线/桌面一致性。若未来明确要求纯离线导入，再单独设计本地转换器。 |
| 正文提取 | `Beautiful Soup` 解析容错 HTML；由“导入选择助手”把页面划成有序内容块，优先语义化 `<article>`、`<main>`、`itemprop=articleBody`，再按段落/标题/代码/表格/链接密度给出建议选中状态。用户可逐块改选；低置信度必须明确提示。算法放独立服务模块，用 30 份不同来源样本校准。 | 直接取 `<body>` 会混入导航/页脚/广告；第一版不引入第二种运行时。若复杂站点样本持续达不到验收门槛，可用 Mozilla Readability 的结果做离线对照，再决定是否引入。 |
| HTML→Markdown | `markdownify` + 明确的标签/属性规则；它已有标题、链接、图片、表格、代码语言回调等转换选项，复杂结构只补定点规则。固定依赖版本、记录转换器版本并锁定测试样本。 | 正则全局替换无法正确处理嵌套和无效 HTML；用模型转换不可复现、成本高且可能改写事实。 |
| 预览与编辑 | 结果映射现有 `ParsedMarkdown`/`BlogDraft` 字段，在现有 Vditor `wysiwyg` 和 Markdown 阅读预览中展示；仍只把 Markdown 交给文章 API。 | 不把 HTML 放进 `content`，避免阅读、知识索引、原位编辑出现双格式分叉。 |
| 持久化 | 第一阶段无数据库迁移：预览响应只驻留当前请求/前端内存；确认后使用现有按账号/workspace 隔离的本地草稿缓存。发布仍使用 `BlogArticle`、待审 `BlogArticleRevision` 和原有审核。 | 不为一次转换建立永久任务表；若后续批量导入或长时转换，才设计异步任务与清理期限。 |

参考：[Beautiful Soup 官方文档](https://www.crummy.com/software/BeautifulSoup/bs4/doc/)、[markdownify 项目说明](https://pypi.org/project/markdownify/)、[Mozilla Readability 的内容提取与安全说明](https://github.com/mozilla/readability)。选型为本项目的工程判断，不把库本身当成安全过滤器。

## 3. 用户流程

1. 在写作页点“导入”，文件筛选显示 Markdown 与 HTML；选择 HTML 后不立即改动草稿。导入已有内容时，后面“应用到草稿”前显示字段级覆盖差异与明确确认。文件错误、取消或关闭弹窗都保留原草稿。
2. 前端在发送前提示原始 HTML 会上传到当前博客服务端用于一次性转换；显示文件名、大小。可输入“原网页地址”（仅用于相对链接计算与来源说明，服务端**不会访问**该地址），空值也能导入。
3. 服务端返回建议结果、可选“整页”结果、标题/摘要、各内容块的建议选中状态、结构计数、资源清单与警告。界面显示“建议导入”的已选块与“可能是目录/广告/评论”的未选块；用户可勾选/排除并实时查看安全 Markdown 预览。界面不渲染原 HTML，不用不受约束的 `v-html`/iframe。
4. 用户在预览中检查标题、正文、代码、表格和图片警告；可编辑标题/摘要，选择是否将已确认的来源地址作为“原文链接”加入正文末尾。点击“应用到草稿”后沿用现有恢复、冲突和草稿状态提示；可选下载 UTF-8 `.md`。如果随后发布，仍需人工审核，审核前不公开、不索引。
5. 原位编辑已有文章时，首期隐藏 HTML 导入入口，避免将整篇文章静默覆盖并形成错误的待审修订；后续要支持替换，必须带公开版本号与差异预览，复用现有 409 冲突机制。

### 自动建议与人工确认的分工

首期的“导入选择助手”是**确定性决策组件**，无需调用大模型：按 DOM 语义、标题层级、连续段落长度、正文文字/链接比例、代码与表格等信号生成候选内容块；对导航、分享、广告、页脚和大量重复链接降低排序。它只决定**建议勾选哪些原文块**，不摘要、不润色、不改写句子，也不删除未选内容的恢复入口。类似的正文提取思路已有 [Mozilla Readability](https://github.com/mozilla/readability) 作为可对照实现，但其“可能可读”判断也明确可能误报或漏报，因而不能代替用户确认。

块按原文顺序编号，并保留转换后的标题、前两行摘录、文字量、建议原因及安全 Markdown；用户取消/勾选时只拼接原顺序的块，避免重复转换和编辑器游标漂移。得分仅分“建议/待确认/可能无关”，**不是事实正确概率**。当正文候选分数接近、建议结果很短、丢弃文本占比过高或页面有多个主栏时，默认停在待确认状态，不能悄悄导入。即使高置信，应用到草稿仍需用户点击。

如真实样本显示规则难以区分混合页面，再考虑 B-040D 的**可选模型辅助选择**：用户主动点击并同意将限长、去脚本后的块标题/摘录发送到已有写作模型；模型只返回块 ID、选择理由和“不确定”，不得生成 Markdown、修改原文、访问网址或直接保存。服务端只接受确实存在的块 ID 并重新检查权限、长度和费用限额。没有密钥、超时或模型输出无效时退回规则建议与人工选择；在隐私/费用授权及对照评测前不默认开启。先比对 30 份人工标注网页中规则与模型的遗漏/误选率，模型没有明确增益就不引入该路径。

## 4. 转换契约与管线

### API

`POST /api/agent/blog/imports/html/preview/`，只接受真实登录用户的 Bearer access token（沿用当前写作页登录限制），按 JWT workspace 计量限流；不接受角色头冒充。请求：`file`（`.html/.htm`）、可选 `source_url`（只允许 http/https 且长度受限，仅解析不抓取）、`mode=article|full`。上限拟定单 HTML 5 MiB、解析后的节点数与文本长度另设限额；实际代理/body 限额需一并核对。响应使用现有统一错误结构。

成功 `200` 返回例如：

```json
{
  "title": "文章标题",
  "summary": "摘要",
  "content_markdown": "## 第一节\n\n正文…",
  "source_url": "https://example.org/post",
  "mode": "article",
  "stats": {"text_chars": 1200, "headings": 4, "tables": 1, "code_blocks": 2},
  "blocks": [{"id": "b1", "heading": "第一节", "excerpt": "这一节的前两行…", "markdown": "## 第一节\n\n正文…", "recommended": true, "reason": "article 内的连续正文"}],
  "assets": [{"kind": "image", "original": "./post_files/a.png", "status": "missing_local_file"}],
  "warnings": [{"code": "LOCAL_IMAGE_MISSING", "count": 1}],
  "converter_version": "html-md-v1"
}
```

`400` 无效格式/URL/文件、`401` 未登录、`413` 超限、`422` 无可提取正文或乱码无法可靠解码、`429` 超速、`503` 转换服务暂不可用。错误只返回稳定码和可读提示，不能回显原 HTML/异常栈。重复请求没有数据库副作用；请求 ID 可用于排错，日志只记大小、耗时、计数、错误码和脱敏文件哈希，不记网页正文或带查询参数的 URL。

切换“提取正文/整页内容”时，前端保留用户刚选的 `File` 对象并以新 `mode` 再请求一次；服务端不依赖暂存文件或会话状态。切换过程中保留已显示的预览，失败时仍可回到上一结果，不修改草稿。

### 顺序与规则

1. **输入校验**：扩展名、实际内容特征、尺寸、NUL/二进制比例；不能只信上传 MIME。读取字节上限，识别 BOM 与 `<meta charset>`，尝试 UTF-8/常见中文编码并对不确定解码报警；拒绝明显二进制或空页。禁止 XML 实体、外部 DTD、模板执行。
2. **提取**：解析为树；移除不可导入的 `script/style/template/noscript/iframe/form`。`nav/aside/footer` 等区域不建议选入正文，但其可见文字可作为“可能无关”块供用户找回，不能简单永久抛弃其中的正文。按章节/DOM 区域分块，保留标题、段落、引用、列表、表格、`pre/code`、图注和链接。标题优先正文 H1，其次文档 title，最后文件名；摘要取可靠的 meta description 或正文首段，均需截断且用户可改。低分候选和正文文本过短时给警告/备用整页模式，不悄悄改选另一个大块。
3. **资源与链接**：只有用户确认的 http/https 来源 URL 可用于解析相对链接；`javascript:`, `data:`, `file:`, `blob:` 和协议相对 URL 的不明来源均不产生可执行/可加载目标。绝不跟随 `<base>`、重定向、远程图片或 CSS 自动请求。外部图片默认生成“图片：alt（外部链接）”及待处理清单，避免预览时向第三方自动发请求；本地相对图片标“缺资源”，不输出会失效的 `![](...)`。普通安全网页链接可保留并加转义；mailto 可转换为文本或受控链接。图片 URL 中凭据、追踪参数不写日志。
4. **结构转换**：H1 作为文章标题时从正文去重；保留 H2～H6、列表层级、引用、强调、分隔线、代码块与语言、GFM 表格。`pre/code` 内的换行/缩进不归一化，围栏长度要避开代码中的反引号。合并单元格、复杂嵌套表格、数学、Mermaid、视频/交互部件无法保证等价，给明确 `UNSUPPORTED_BLOCK` 警告，尽量保留可读文本/链接，不偷偷丢内容。清理多余空白但不改写正文措辞。
5. **输出安全**：生成 Markdown 前移除原 HTML 和事件/样式属性；URL 做协议白名单；Markdown 中残留的原始 HTML 标签按安全策略转义或删除。预览及最终阅读仍走现有 Markdown→HTML→`xss` 白名单渲染链；后端保存再次执行大小、字段、权限校验。转换器不是 sanitizer，需双层防护。[OWASP 文件上传建议](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)也要求扩展名、内容、大小、权限等多层校验。

最小示例：`<h1>缓存复盘</h1><p>命中率提升 <strong>12%</strong>。</p><pre><code class="language-python">print("ok")</code></pre>` 转为标题字段“缓存复盘”，正文 `命中率提升 **12%**。` 和带 `python` 语言标记的代码块；页面导航、脚本和 CSS 不进入草稿。该映射是设计例子，待 B-040A 的样本测试证明。

## 5. 图片与“完整网页”第二阶段

首期**不自动下载远程图片**：服务器下载任意网页或图片会产生 SSRF、版权和成本风险；第三方图片也可能失效并暴露读者访问。用户可在现有 Vditor 中手动上传经许可的图片，复用已验证的 PNG/JPEG/GIF/WebP 校验、5 MiB 图片上限和受控 `/media/blog/` 存储。HTML 里 `data:` 图片、SVG 和 CSS 背景图均列警告，不直接发布为附件。

第二阶段接收浏览器“保存完整网页”导出的 `.zip`（单个 HTML + 图片目录，前端明确说明打包方法），只处理事先约定的目录与文件类型。先做 ZIP 条目数量、压缩/解压体积、单文件、层数、路径穿越与符号链接限制；在隔离临时目录中解包，按原路径精确匹配图片，经现有 `blog_media` 验证再上传并把 Markdown 图片改写为本站 URL。任一图片失败先给缺失清单，**不提交文章**；已上传而用户取消时需要临时对象清理/引用计数方案，因此该阶段不能简单沿用第一阶段无持久化的假设。此阶段单独验收后开放，不随首期接口默认启用。

## 6. 安全、权限与可恢复性

- 转换接口有登录、workspace、限流、超时、CPU/节点/文件上限；不执行 JS，不联网抓取，不保存 HTML 到媒体库或公开目录，不在日志、报错或 Agent 轨迹中复制正文。HTML 内的“忽略前文”等指令只是文章文本，不会送进模型。
- 输出草稿在用户点击应用前保持原状；与现有账号/workspace 隔离缓存和多标签冲突检测一致。若本机草稿存储失败应明确提示并提供 `.md` 下载，不能显示“已保存”。
- 公开发布路径不变：新文章审批后才入知识库；从其他网站导入的内容要由作者确认使用权限与署名，不默认生成原创声明；来源 URL 不代表授权。
- 首期无数据库迁移且新功能可由前端入口/独立路由开关关闭。回滚不会删除原有文章或草稿；用户在回滚前可下载生成的 Markdown。部署时只有新增依赖、接口和请求体限制需要确认。

## 8. 待实现前确认的最小产品规则

默认导入**文章正文而非整页**；保留“整页内容”作为可选预览。外部图片不自动嵌入或下载，本地相对图片需要资源包阶段；源地址可选但必须由用户确认。导入只写新建草稿，发布仍走当前审批。以上规则优先保证内容可编辑、来源可核对、草稿不丢和公开阅读安全；若真实样本与用户任务推翻其中一项，先更新本文和验收样本再调整实现。
