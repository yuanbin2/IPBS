# 浏览器扩展连接博客设计 V2.7

> 状态：设计，尚未实现。已于 2026-10-03 对照当前代码核对接口：现有链接预览 API、Vue 写作页和本机草稿缓存可复用。适配 B-041 力扣链接建卡与本人笔记导入；不改变 B-041C 的授权前提。本文把“在当前网页上点一下就生成可编辑草稿”拆成可先交付的安全范围与需外部授权的内容范围。

## 1. 结论与边界

浏览器扩展在用户点击按钮后可以读取当前打开的网页，并将经过用户确认的信息交给博客。Chrome 的 `activeTab` 只在用户主动触发时给当前标签页临时访问权；配合 `scripting` 可读取页面。Edge 对同类扩展 API 基本兼容，但仍需实际侧载测试。[Chrome activeTab 文档](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)、[Edge 兼容文档](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/port-chrome-extension)。

扩展解决的是“服务器无法访问动态页面 / 跨域 / 登录态页面”的一部分**技术**问题，并不赋予复制、存储和公开转载网页内容的权利。当前[力扣中国服务条款](https://leetcode.cn/document/terms/)第 3.1.6 节限制未经书面授权的复制、改编和传播，第 3.1.7 节限制干扰服务正常运行的未授权插件；[LeetCode.com 条款](https://leetcode.com/terms/)直接禁止 crawling/scraping/spidering，并将题目、题解、图片列为内容。因此不能把扩展设计成绕开平台限制、自动搬运完整题面和他人题解的工具。是否可以转载某个具体内容，还需核对其作者、许可及用途。

### 可先做的第一阶段

在力扣题目页点击扩展图标，读取当前页 URL、页面标题、可见题号候选；弹窗展示并让作者核对。作者可以补充**自己有权再次使用**的代码或笔记，然后把这些候选数据一次性交给博客写作页。写作页调用现有 B-041 `link-preview` 生成“来源卡 + 解题模板”，经用户确认后应用到**本机未提交草稿**。用户在现有 Vditor 可视化编辑器中修改；只有主动点击提交才会创建服务器文章和审核请求。扩展不抓题面正文、示例、约束、图片或他人题解，不读取力扣 Cookie、站内接口或登录凭据。

### 有授权才考虑的第二阶段

如果取得明确覆盖访问方式、复制、存储、改编、图片及公开展示范围的书面许可，才设计页面内容采集或许可数据连接器。即使获许可，也必须逐块标明来源和授权范围，并只允许被许可的内容进入公开审核。没有许可时，第一阶段的链接建卡继续可用；“我能在浏览器里看到”及用户勾选确认都不等同于转载授权。

## 2. 用户流程

1. 用户在 `leetcode.cn/problems/{slug}/` 或 `leetcode.com/problems/{slug}/` 的题目页点击扩展图标。其他页面显示“目前只支持力扣题目链接”以及手动粘贴链接入口。
2. 扩展仅在此次点击后读取当前标签页；展示规范来源链接、标题/题号候选和“这些字段来自页面，需核对”。页面结构异常时只保留 URL，不能把广告、评论或登录页当成题目。
3. 用户选择“发送链接和我的笔记”。笔记输入框由用户主动填写或粘贴；可以从用户明确选择的文本进入笔记候选，但在发送前必须预览、编辑并确认其有权使用。默认不选取整页、题面、他人题解或图片。
4. 扩展打开博客 `/blog` 页面，用一次性消息交接最小数据。博客现有导入弹窗显示来源卡、模板、即将追加的本人内容，以及“取消 / 应用到本机草稿”。取消不修改现有文章或缓存；已有本机草稿必须先显示差异/覆盖确认。
5. 作者继续在原有写作页编辑、保存和提交审核。公开文章保留原题链接，引用他人内容只用链接和作者自己写的说明。

扩展只减少“复制链接、手填题号和切换页面”的重复动作。它不承诺在任何力扣页面结构、登录状态和浏览器版本下都能识别标题；识别失败时回退到已有的 B-041 手动链接导入。

## 3. 架构与权限

```text
题目页 --用户点击--> Manifest V3 扩展 popup
  --activeTab + scripting，提取最小候选--> 弹窗预览与用户确认
  --storage.session 存临时数据、打开博客 tab（URL 只有随机 nonce 和扩展 ID）
  <--博客页以 externally_connectable 消息消费一次-- 扩展 service worker
  --现有 B-041 link-preview（博客页带自身登录态调用）--> Vditor 本机草稿
  --作者主动提交、现有审核和公开阅读链路--> 文章
```

- **与现有代码核对**：`backend/apps/agent_api/views/blog_imports.py` 已有 `POST /api/agent/blog/imports/leetcode/link-preview/`，内部复用 `services/leetcode_link_import.py` 的严格 URL 解析；`frontend/src/features/blog/components/LeetcodeImportDialog.vue` 已能预览模板；`BlogWriter.vue` 已有覆盖旧草稿的确认；`BlogView.vue` 的新稿保存在本机并由 `publishDraft()` 主动提交。当前 `POST /api/agent/blog/articles/` 会立即产生审批请求，不能把它称为“只保存私有草稿”。
- 目标浏览器：先 Edge，复用 Chromium Manifest V3；Chrome 为兼容目标。权限仅 `activeTab`、`scripting`、`storage`；不申请 `<all_urls>`、`cookies`、`webRequest`、持久的力扣站点权限或任意网络 `host_permissions`。扩展不直接请求后端，因此不用新增配对码、服务端 clip API、数据库迁移或 CORS 放宽。
- **交接协议**：popup 从 `chrome.tabs.query` 得到浏览器提供的当前 tab URL，调用 `chrome.scripting.executeScript` 只读取标题/题号候选；用户确认后发给 service worker。worker 生成至少 128-bit 随机 nonce，将最小 JSON、创建时间和即将打开的 tab ID 暂存于默认不向 content script 暴露的 `chrome.storage.session`，调用 `chrome.tabs.create` 打开选定的博客 `/blog#clip=<nonce>&ext=<extension-id>`。URL 绝不放标题、笔记、JWT、Cookie 或完整 Markdown；可在 tab 创建后登记其 ID，失败则清除临时数据。
- 博客页启动并确认当前用户已登录后，解析并立即从地址栏清除 fragment；调用 `chrome.runtime.sendMessage(extensionId, {type:'blog.clip.consume', nonce, version:1}, callback)`。`externally_connectable.matches` 在构建时只包含本机调试地址及已知生产站点；worker **再次**以完整 `sender.url` 检查 origin、路径、tab ID、nonce、版本、过期时间与一次性状态，再返回数据并删除。仅靠 manifest match pattern 不足以区分本机端口。扩展 ID 由 `chrome.runtime.id` 在打开博客时带给页面，不硬编码侧载 ID。[Chrome 网页与扩展消息文档](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)、[externally_connectable 文档](https://developer.chrome.com/docs/extensions/reference/manifest/externally-connectable)、[storage.session 文档](https://developer.chrome.com/docs/extensions/reference/api/storage)。
- 默认站点为当前 `start.bat`/`start.sh` 启动的 `http://127.0.0.1:8001`；前端 Vite 独立调试通常是 `http://127.0.0.1:5173`，桌面默认前端端口 **5174 不变**。这些是不同 origin，全部必须在开发构建中显式登记并逐一测试；生产只使用构建时明确配置的 HTTPS 博客 origin，不接受页面 DOM 输入或任意用户填写的回调地址。若实际生产域名尚未确定，先只交付本地侧载包，并说明生产构建待配置。
- 博客收到数据后只**预填**现有 `LeetcodeImportDialog`，调用原有 `link-preview` 做后端二次校验；标题和题号保留“待确认”标记。用户按导入弹窗确认后才走 `BlogWriter` 既有 `applyImportWithAssets` / 本机草稿冲突逻辑。若用户未登录，提示“登录后重新从扩展发送”，不消耗或持久化笔记。不可由扩展直接提交文章、创建审批或修改现有文章。
- 页面内容是**不可信输入**：从 DOM 返回纯文本而非可执行 HTML，消息与后端二次校验，限制单次体积和频率；用户笔记在页面预览时走现有 Markdown 安全渲染。不要让页面脚本指定 extension worker 的任意操作或目标地址。[Chrome 扩展消息安全文档](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)。
- 采集失败可重试或手动输入；部分字段失败不修改原草稿。不要记录题目正文、笔记、nonce 或访问令牌。

## 4. 不采纳的捷径

| 方式 | 原因 |
| --- | --- |
| 服务器用用户 Cookie 请求力扣内部 GraphQL | 增加凭据泄露与接口变化风险，也不解决访问/转载许可。 |
| 扩展后台自动遍历题库、抓整页或抓 Premium/比赛内容 | 超出用户主动单页操作，易触及条款、规模与内容权利边界。 |
| 把完整题面/题解先存为私有草稿，之后再公开 | 私有存储也涉及复制权和平台条款，不能当成当然允许。 |
| 扩展拿博客长期 JWT 或复用前端 refresh Cookie | 页面与扩展跨信任边界，长期凭据一旦泄露影响整个账号；本设计的扩展完全不接触博客凭据。 |
| 仅靠 CSS 选择器和“成功”提示 | 力扣页面结构会变化；必须有候选预览和手动回退。 |

## 7. B-043A/B 实现记录（2026-10-03）

### 7.1 落地范围

**扩展（`browser-extension/`）**：MV3，权限仅 `activeTab`/`scripting`/`storage`；无 `cookies`、`webRequest`、`tabs`、`host_permissions`，无常驻 content script 与力扣后台监听。

- `shared/protocol.js`（纯函数，Node 可测）：`parseProblemPageUrl` 严格判定精确域名与 `/problems/{slug}/`（拒绝子域/IP/凭据/端口/百分号编码/反斜杠/控制字符/大写或非法 slug/多段路径/超长/非 http(s)）；`deriveCandidatesFromTitle` 从 `document.title` 派生题名/题号候选并标“待确认”；`sanitizeOwnNote` 限制笔记 16 KiB；`createNonce` 128-bit 加密随机；`buildClipRecord` 限制整条 24 KiB；`validateConsume` 做消息类型/版本、origin 精确相等（协议+域名+端口）、targetTabId、nonce、TTL 校验。
- `shared/clip-flow.js`：`prepareClip` 只接受浏览器提供的当前 tab URL（或用户手动粘贴的合法链接），用户点击后才读有限纯文本候选，暂存记录→`chrome.tabs.create` 打开博客→绑定 tabId，失败清理暂存；`consumeClip` 先读后删记录，内存 `consumedNonces` 保证同 worker 实例内并发只成功一次。
- `background.js`：只处理 `blog.clip.consume`；`externally_connectable.matches` 只登记本地调试 origin（`http://127.0.0.1:8001|5173|5174`），并再次用完整 `sender.url` 校验。
- `popup.html/js/css`：显示当前 tab 识别结果、候选字段编辑、笔记输入与章节选择、博客 origin 下拉（只读允许列表，记住上次选择）；读不到 tab 或非题目页时给出手动粘贴入口与手动复制原链接回退；任何失败都有可读反馈与“重试”。
- `README.md`：侧载步骤、地址配置、使用步骤与常见错误诊断表。

**博客页接入**：`frontend/src/features/blog/utils/clipHandoff.ts` 负责 fragment 解析（nonce 格式 + 扩展 ID 校验）、`history.replaceState` 清除、登录态检查、`chrome.runtime.sendMessage` 一次性消费与失败原因映射，并对扩展返回内容做不可信输入清洗（URL 白名单正则、限长、控制字符剥离）。`BlogView.vue` 在 `onMounted` 的登录态就绪后消费，成功则预填草稿；写作台已打开时不重建工作上下文（否则换 context 会重挂载 BlogWriter 把刚打开的弹窗关掉）。`BlogWriter.vue` 新增受控 `leetcodeDialogOpen`/`clipCandidate` 与 `consumed` 事件；`LeetcodeImportDialog.vue` 增加候选来源说明与“交接笔记追加到所选章节”的插入逻辑，仍走原有预览与 `BlogWriter` 覆盖确认。

**截图去向拆分：仅保存图片到本机（2026-10-06）**：用户要求把长截图拆成「可用博客」与「仅保存图片」两条独立去向，后者保存后不跳转博客。实现：扩展弹窗新增「截图去向」单选（默认到博客识别，选择写入 chrome.storage.local），随 capture 消息透传 saveMode；background 在两种采集入口分流——“用时”将 sessionInput 改走新增的 `shared/screenshot-flow.storeLocalShot`（与 saveScreenshotSession 相同的校验与暂存，但不打开博客、不占用待接收名额），随后经 offscreen 文档完成拼接下载：`manifest` 增加 `offscreen`/`downloads` 两项窄权限，新增 `offscreen-stitch.html/.js` 私有文档（读取本扩展 IndexedDB 的 tile，用与前端一致的几何拼成一张 PNG 存下载目录，成功后清理会话，失败保留到 TTL 便于博客页消费或重试）。拼接几何抽成纯函数 `shared/longshot-stitch.js`（DPR/选区换算、范围外 tile 跳过、画布上限缩放，canvas/解码经 adapter 注入），7 例 Node 单测覆盖。长图 HUD 与状态文案按去向切换（标题、完成按钮提示“保存图片/发送到博客”）。单测 64/64、截图相关 e2e 17/17 通过；offscreen 文档在真实 Edge 上下载落盘、以及“仅保存图片”按钮路径尚未自动化（截图 e2e 走 mock 扩展，不起 offscreen），需人工侧载验收。

**仅保存图片的两次返工与最终架构（2026-10-06 晚）**：首版实现完全没生效，返工两次后定位到四个真实故障。其一，MV3 service worker **不能给自己发 runtime.sendMessage**（offscreen 收不到，worker 甚至被重启）——改为页面完成后主动回传。其二，反向先 \`chrome.runtime.connect\` 也会丢消息：页面还没注册监听时连接即断开——改为 offscreen 加载完成后主动 sendMessage 回结果。其三，扩展页面 CSP 禁止 inline script，把拼接逻辑写进 HTML \`<script>\` 会导致页面静默不执行——拆成外部 \`offscreen-stitch.js\` / \`stitch-page.js\`。其四，拼接几何读的字段名与 shot 记录真实结构不符（记录里是 \`viewport:{width,height}\` 与 \`covered:{top,bottom}\`，不是 \`viewportWidth/viewportHeight\`）——已兼容两种形状并补单测。另外 MV3 worker 空闲即回收，120 秒等待链会在回收后丢失：最终架构改为**拼接页直接通知 HUD 标签页**（成败都直达用户），worker 只做短等待（8 秒判定 offscreen 是否可用）。offscreen 仍是无感首选；在其不执行的环境（如 headless）自动改开一个扩展标签页 \`stitch-page.html\` 完成拼接下载并自动关闭。权限新增 \`offscreen\`/\`downloads\` 两项窄权限（已写入 V2.7 权限边界说明与 README，并有 e2e 断言防止后续漂移）。顺带修掉三个既有用例缺陷：长图 OCR 块断言缺超时（默认 8 秒 vs 实际 10 秒以上）、按钮名失配（用例找“从整张长图框选配图”，实现是“手动框选页面配图”）、权限集合断言未含新权限。验证：扩展单测 64/64、前端单测 58/58、\`npm run build:check\`、隔离侧载 e2e 新增“仅保存图片”用例通过（不打开博客、下载完成且 PNG、会话清理）；截图三套件连跑有 1 个登录态 flaky（单独复跑通过）。测试环境（playwright artifacts）会强制下载文件名为 UUID，因此用例只验证“下载完成且为 PNG”；真实 Edge 的 \`chrome.downloads.download\` filename（long-screenshot-时间戳.png）需人工侧载确认。

**“仅保存图片”与博客彻底解耦（2026-10-06 深夜）**：用户要求保存图片后完全不经过博客。此前的实现仍有三处隐藏耦合：弹窗必须先在“博客地址”下拉里选一个允许列表 origin 才能截图（博客没启动就用不了）、capture 消息始终带 targetOrigin、失败文案引导“改用博客识别”。现已全部拆除：`storeLocalShot` 去掉 origin 校验（`saveScreenshotSession` 的博客路径校验不变），popup 新增独立的 `#shot-origin` 下拉并默认收起——选“仅保存图片”时隐藏博客地址选择、capture 消息不带 targetOrigin，弹窗默认方向也改为“仅保存图片”；HUD 与提示文案只讲截图本身，不再提博客。保存图片现在只依赖扩展自己（offscreen/标签页拼接 + downloads），博客未启动、未登录、未配置地址都能用。
