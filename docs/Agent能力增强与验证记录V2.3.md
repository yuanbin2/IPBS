# Agent 能力增强与验证记录 V2.3

> 2026-10-02。本记录区分确定性功能、模型替身测试与真实模型质量；本轮未调用付费模型，也未部署服务。

## 本轮发现与改动

| 链路 | 问题 | 改动及原因 | 本地证据 |
| --- | --- | --- | --- |
| SQL Analysis Agent | 汇总查询跨工作空间计数，可能暴露其他租户的业务规模。 | 所有知识库、文档、文章、评论、会话聚合均按当前 JWT 对应 workspace 过滤；评论通过文章的 workspace 过滤。沿用 ORM 白名单聚合，不接受模型生成任意 SQL。 | 含本空间和其他空间文章/评论的 API 测试，返回只含本空间数量。 |
| Review Agent | 原来只重复静态检查清单，不能判断用户说的“上一条回答”。 | 将当前会话最近消息的已保存来源传给审查 Agent；审查上一条 Agent 回答是否有来源及引用编号，给出可核对来源和缺口。无上一条回答时说明无法审查；明确提示引用存在不等于事实正确。显式审查追问优先按当前意图路由，避免上一轮检索关键词抢路由。 | 来源和引用的 API 测试；隔离 Edge 流式统计→审查→刷新历史回放。 |
| Internet / RAG / MCP Supervisor | 回答之外的工具输出、来源片段或轨迹可带模型/网页异常中的敏感值；联网同步与 SSE 路径处理不一致。 | REST 与 SSE 的最终输出统一脱敏回答、工具输入/输出、来源标题/片段和轨迹；流式轨迹也做脱敏。联网 SSE 保留实际 Internet Agent 身份，避免显示错误的 Supervisor 决策。 | 注入测试密钥的联网工具替身，REST/SSE 均不返回原值；原有联网与路由测试全量通过。 |
| Public Blog Agent | 模型异常文本可能进入访客轨迹，生成内容与历史回放缺少统一输出脱敏。 | 异常轨迹只保留异常类型；公开回答及来源、轨迹在返回和持久化前脱敏，读取历史也对遗留内容脱敏。 | 注入测试密钥的公开回答和旧历史记录测试通过。 |
| 模型故障回退 | 工作流或联网生成异常把原始异常消息展示给用户，可能包含内部请求或上下文。 | RAG 与联网生成失败轨迹只保留异常类别；保留原有确定性回退、工具结果和来源路径。 | 默认及强安全完整后端回归通过。 |

## 测试结果

- 改动前离线后端基线：默认配置 **195/195**。
- 改动后完整后端：默认配置 **199/199**，强安全配置 **199/199**。测试环境清空模型 API Key，使用本地 hash embedding 和 mock；Ruff/Black 检查通过。
- 前端 `npm run build:check` 通过。原有隔离 Edge 完整浏览器套件 **18/18**；新增 Agent 对话浏览器专项 **1/1**，覆盖流式统计、审查和历史恢复。
- 没有模型或数据库迁移；桌面默认端口 **5174** 未变，浏览器测试使用独立 5185 端口。

## 仍需外部验收

本地通过只能证明路由、权限、状态、输出协议和故障回退能工作，不能保证真实模型答案正确。发布前冻结至少 40 条覆盖 RAG、公开博客、联网、写作、审查和拒答的用例，人工双人标注问题、期望来源与事实点；在有明确预算和测试密钥的隔离环境分别记录真实模型的来源命中率、事实错误率、拒答准确率、成本和 P95 延迟。联网搜索还需真实提供方故障演练，SQL 聚合需真实 PostgreSQL 跨工作空间验证，SSE 需实际 Nginx 首事件验收。远端 CI 和 Railway 实站仍按发布阻断清单执行，不能用 mock 结果宣称模型质量达标。
