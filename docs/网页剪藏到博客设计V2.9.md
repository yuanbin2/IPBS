# 网页剪藏到博客设计 V2.9

> 历史状态快照（2026-10-03）：当时通用剪藏尚未实现，默认目标是本机博客草稿。后续 V2.9.1 及当前扩展已取代该流程，本文只保留早期设计与边界，不代表当前功能状态。实际网站兼容性须用真实 Edge 页面验收，无法承诺所有网页无损转换。

> 后续产品决定（2026-10-03）：扩展改为**通用网页剪藏，默认导入我的私有笔记**，替代旧力扣专用扩展入口；博客草稿是可选目标。实施时以[当前通用剪藏说明](../browser-extension/README.md)覆盖本文关于“保留旧力扣扩展 UI / 以文章草稿为默认目标”的表述。站内手动导入力扣链接和现有文章数据不属于替换范围。

## 1. 现状与选型

| 现有能力 | 仓库接点 | 设计结论 |
| --- | --- | --- |

选择 [MarkDownload](https://github.com/deathau/markdownload) 作为内容抽取与转换的参考基础：它已使用 [Mozilla Readability](https://github.com/mozilla/readability) 提取正文、[Turndown](https://github.com/mixmark-io/turndown) 转 Markdown，支持选中区域和图片下载选项。MarkDownload 代码是 [Apache-2.0](https://github.com/deathau/markdownload/blob/main/LICENSE)。但当前上游仓库的 `src/manifest.json` 是 **Manifest V2**，并申请 `<all_urls>`、下载和剪贴板等权限；现有博客扩展是 MV3 且按点击临时授权。故移植经审查的抽取模块/规则到现有扩展、保留其原有许可声明和修改说明，比直接替换整个扩展更符合本项目的兼容性与权限边界。上游版本须固定到具体 commit，记录被复用文件及其依赖的许可证。不要仅凭本设计断言上游打包代码都可直接运行于 MV3 service worker。

## 2. 目标、非目标与用户流程

### 首期目标

1. Edge 优先，Chrome 兼容：在普通文章网页点击扩展，选“剪藏正文”或“仅剪藏当前选中内容”。扩展给出标题、来源、内容范围、Markdown 排版预览、图片数量和可编辑的来源说明。
2. 用户点击“送到我的博客”后打开站内新稿写作页。站内做二次转换与块选择，展示标题、正文、外链图片状态和警告；用户可以删除多余块、修标题、选图或忽略缺图，再点“应用到草稿”。
3. 既有草稿不被静默覆盖。应用前显示字段级差异/覆盖确认；取消、超时、图片失败和登录失败均保留原草稿。
4. 成功应用后使用现有 Vditor 可视化编辑，作者可以继续改写、补充自己的观点；只有主动提交才进入原有审核链。
5. 保留原始来源 URL、页面标题、剪藏时间、抽取器版本和用户最终选择范围，用于预览和可追溯性；默认只将用户明确选择的来源说明写入 Markdown，不在文章中偷偷加入追踪参数。

### 明确非目标

不自动遍历网站、不批量爬取、不绕过登录、付费墙或站点技术限制，不读取 Cookie、网页凭据或博客 JWT，不把页面脚本指令交给 AI，不自动发布。受限页面或内容授权不明时显示“只能导入有权使用的内容”。力扣页面继续走 B-043 链接建卡模式；不得把通用剪藏按钮用于复制完整题面或他人题解，除非 B-041C 的授权条件另行满足。页面可见内容不等于拥有公开转载、图片再分发的权利。

### 流程

```text
当前网页 --作者点击扩展--> 当前 tab 临时授权
  -> 克隆当前 DOM / 用户选区 -> MarkDownload 移植的 Readability + Turndown 规则
  -> 扩展弹窗显示 Markdown 预览、来源和资源警告
  -> 作者确认 -> 扩展 session 中暂存有界的正文 HTML + 元数据
  -> 打开博客 /blog#clip=<随机 nonce>&ext=<扩展 ID>&kind=web
  -> 博客登录态确认并清理 fragment -> 按 origin、tab、nonce、TTL 分块取回
  -> 把正文 HTML 构造为 File，调用已有 HTML 预览 API
  -> 站内逐块核对、处理图片 -> 显式应用到本机草稿
  -> 可视化编辑 -> 作者主动提交 -> 现有审核
```

作者第一次打开扩展时只看见两个明确动作：“剪藏正文”“剪藏选中内容”。读取发生在点击后，不常驻监视标签页。预览应区分“扩展初步抽取”和“博客最终导入预览”；两次转换结果有差异时以站内最终预览为准，并告知用户检查。选择内容为空、登录页、只有导航、正文过短或抽取结果与页面文字差距大时，给出重试/选区/手动保存 HTML 回退，不显示“成功”。

## 3. 抽取与格式规则

- 在 `chrome.scripting.executeScript` 的隔离上下文读取**当前渲染后的 DOM**，对克隆树运行抽取，不修改原网页。记录浏览器给出的 tab URL、`document.title` 和安全的 canonical 候选；canonical 与当前页面不同站或含凭据时必须人工确认，不作为抓取地址。
- 正文模式优先 Readability 结果；低置信或空结果提供“选中内容”“整页预览”回退。选区模式只转换用户明确选中的 DOM 片段。防止将导航、评论、推荐文章等误判为正文；原文块顺序不得改变。
- MarkDownload 的 Turndown/GFM 规则用于扩展预览；保留 H1～H6、段落、链接、图片 alt、嵌套列表、引用、代码语言/缩进、表格和分隔线。数学、Mermaid、嵌入视频、交互图和跨行/跨列表表格不可保证等价，显示具体警告并保留可读文本。
- 使用真实 DOM 的 `currentSrc`、`srcset`/懒加载属性作为图片地址候选；只允许绝对 HTTP(S)，对相对路径基于用户确认的原网页 URL 解析。`blob:`、`data:`、canvas、CSS 背景、站点需登录的图片列入“需要手动补图”，不能当作已保存。
- 后端仍按 B-040 处理不可信 HTML：大小/节点/文本上限、去脚本与危险属性、URL 协议白名单、输出 Markdown 安全渲染。扩展抽取器不是安全过滤器。页面中的“忽略之前指令”等内容仅作为文章数据。
- 对标题、段落、列表、表格、代码、数学等维护带人工预期的网页夹具；转换不得改写句子与数字。作者可以在博客里增删块。最终 Markdown 才进入文章内容字段，原始 HTML 不发布也不存为公共附件。

## 4. 跨扩展与站内的协议

### 4.1 版本和消息

保持 v1 的力扣消息行为不变，新增 `kind=web` 的协议 v2。v2 元数据至少包含 `kind`、`version`、`nonce`、`sourceUrl`、`titleCandidate`、`captureMode`、`capturedAt`、`extractorVersion`、`htmlUtf8Bytes`、`chunkCount` 和 `sha256`。正文只放 `chrome.storage.session`，不放 URL、日志、`storage.sync` 或长效 `storage.local`。单次正文 HTML 上限暂定 **2 MiB UTF-8**，每片不超过 **64 KiB**，TTL **5 分钟**；这低于当前 HTML 预览 API 的 5 MiB 上限，并为 session 总额、并发和元数据预留空间。用户超限时可下载 `.md` 或使用现有 HTML 文件导入，不悄悄截断。每次最多两条待消费剪藏；新请求需提示用户或清理已过期记录。

站内按 `get-meta` → `get-chunk(index)` → 本地拼装并验 SHA-256 → `ack` 的顺序读取。扩展每次响应都检查消息类型/版本、随机 nonce、到期时间、完整 `sender.url` 的 **scheme + host + port + `/blog` 路径**、目标 tab ID、片序和重复消费状态；失败后不返回正文。`ack` 或取消后删全部临时块；过期清理是兜底。服务 worker 重启、分块缺失、hash 不符、浏览器退出和 tab 关闭须能得到确定性错误并回到重试。不要把全部正文塞进一次 `sendMessage`、URL fragment、窗口名或剪贴板。

生产扩展 `externally_connectable.matches` 由构建参数精确列出 HTTPS 博客域名；开发仅列 `127.0.0.1:8001`、`:5173`、`:5174`，当前桌面默认 **5174 不变**。虽然 manifest 只能按 pattern 匹配，worker 必须再比较完整 origin 与路径。不能接受网页传来的任意目标服务器或跨域回调。扩展本身不直接访问博客 API、不持有博客 access/refresh token；博客页用自身既有认证发预览请求。博客站未登录时不读取/应用正文，提示先登录后重新发送。

### 4.2 API 和前端接入

第一版不新增后端剪藏专用持久化接口。站内收到 v2 HTML 后在内存中构造 `File([html], 'web-clip.html', {type:'text/html'})`，交给现有 `HtmlImportDialog`，自动填入原网页 URL 并触发 `POST /api/agent/blog/imports/html/preview/`。后端须重新验证输入，不信扩展提供的标题或已清理标记。弹窗应支持“外部 File + 初始 URL + 初始模式”，保留文件手选入口，且不要破坏 B-040/B-041 与 v1 扩展。若现有转换器对 Readability 的简化片段再次选块导致内容丢失，先用夹具证明问题，再加 `mode=clip` 的有限规则；不能绕过后端转换与校验直接把扩展 Markdown 写进草稿。

应用到草稿复用 `BlogView` 当前的图片处理、冲突确认和缓存逻辑。不能直接 POST `/api/agent/blog/articles/`，因为当前该接口会生成审批请求。来源记录首期在本机导入预览与作者选择的正文末尾，不新增数据库列；若需要可查询的结构化溯源，另开迁移设计并处理原有文章兼容。

### 4.3 可核对的消息契约与状态

下例表示字段语义，不要求照抄字段名；实现前应把实际 TypeScript/JavaScript 类型、最大值、版本兼容表和错误码固定在共享协议模块。URL 仅携带 `clip`、`ext`、`kind=web`，这里的正文 `html` **绝不能**出现在 URL：

```json
{
  "type": "blog.webclip.get-meta",
  "version": 2,
  "nonce": "32位十六进制随机值"
}
```

```json
{
  "ok": true,
  "meta": {
    "kind": "web",
    "version": 2,
    "sourceUrl": "https://example.org/post",
    "titleCandidate": "网页标题",
    "captureMode": "article",
    "capturedAt": "2026-10-03T10:00:00.000Z",
    "extractorVersion": "markdownload-port-1",
    "htmlUtf8Bytes": 182536,
    "chunkCount": 3,
    "sha256": "整个 UTF-8 HTML 的十六进制 SHA-256"
  }
}
```

然后站内以 `blog.webclip.get-chunk` 加 `index=0..chunkCount-1` 顺序请求。响应只含该片字符串及 `index`，不含跨片可执行脚本。采用 UTF-8 编码后分片，不能把一个多字节字符截断；站内拼好后核对字节数和 SHA-256，再允许打开 HTML 预览。核对失败不调用后端、不修改草稿。`blog.webclip.ack` 在站内成功接收完整内容后删除会话记录，取消也发送清理消息；若中途失败保留到 TTL 便于作者重试，但不得让别的 tab 消费。同一 nonce 最多完成一次 `ack`，已消费的 nonce 不再提供片段。

错误码至少区分 `not_authenticated`（站内自身状态）、`origin_mismatch`、`tab_mismatch`、`expired`、`replayed`、`chunk_missing`、`size_limit`、`checksum_mismatch`、`extract_empty` 和 `extension_unavailable`；用户界面给出能操作的回退，不显示内部堆栈。状态顺序为 `idle → extracting → preview → prepared → receiving → verifying → import_preview → applied`，任一步都可 `cancel/failed`，只有 `applied` 才改本机草稿。旧 v1 `blog.clip.consume` 仍按旧字段/限制处理，不在 v2 分支重解释。

## 5. 图片处理与失败语义

| 图片来源 | 首期动作 | 结果 |
| --- | --- | --- |
| 公网直链 HTTP(S) | 站内确认后复用受限图片抓取接口，服务端校验 DNS、连接 IP、重定向、类型、大小与存储读回。 | 成功才改 Markdown 为本站 `/media/blog/...`；失败保留草稿并列出具体图片。 |
| 本地相对文件 / `file:` | 允许用户选择配套文件/文件夹，用现有图片上传与文件名匹配。 | 未匹配则阻止应用或由作者明确选择文字占位。 |
| 登录态图片、`blob:`、canvas、CSS 背景、跨域拒绝或防盗链 | 首期不自动携带站点 Cookie 去抓，不依赖 MarkDownload 的“下载到浏览器文件夹”作为本站资源。 | 给出可手动上传/忽略的警告，不能承诺一定获取。 |

当前远程抓图为每用户每小时 20 次，且要求 operator/admin；图片上传也有角色限制。实施前应在真实普通账号和 operator 账号各走一遍，形成产品决定：首期只给有上传权限的作者、还是增加受控的普通作者配额。若调整，必须同时做限流、workspace/作者隔离、清理未引用对象与真实 Bucket 验收，不要因剪藏功能顺手取消权限。大量图片应显示总数、预算和处理进度；一张失败不能留下“成功应用但图片外链失效”的文章。源站禁止访问或资源已经失效时不能保证自动获取。

## 6. 安全、许可与隐私

1. 权限最小化：初版仍用 `activeTab`、`scripting`、`storage`。如保留 MarkDownload 原有“下载 Markdown”功能才申请 `downloads`；不申请 `<all_urls>`、cookies、webRequest、长期站点 host 权限。只允许用户点击后处理当前活动标签页，禁止自动遍历全部标签。
2. 二次开发许可：固定 MarkDownload 上游 commit，保留 Apache-2.0 LICENSE、已有版权与 NOTICE（若存在），修改过的复制文件标记改动；Readability 的 Apache-2.0 和 Turndown 的 MIT 许可一并记录。项目名称、图标和发布页不冒充上游官方。
3. 网页来源与转载：扩展只解决格式转换。确认页显示原链接、作者/站点候选及“我有权将所选内容存储/改编/公开”的操作说明；默认进入未提交草稿，公开仍经原有审核。不得针对力扣、付费或受限制站点设计绕过路径。
4. 隐私：网页可能含私有资料。弹窗显示即将传到博客服务端的范围；默认不上传未选中的网页区域。日志只记请求 ID、耗时、字节数、错误码和去标识统计，不记正文、带参数 URL、图片鉴权信息、nonce 或令牌。临时数据在消费/取消/过期后删除。
5. 隔离：不能在页面主世界执行网页提供的脚本；不能用 `eval`、远程 CDN 代码、任意 `postMessage('*')` 或不受限 `v-html`。来源 HTML、Markdown、URL 和图片都是不可信输入，最终阅读页继续走 XSS 防护。

## 7. 分阶段实施、测试与验收

| 阶段 | 交付 | 验收门槛 |
| --- | --- | --- |
| W-01 技术小样 | 固定上游版本、许可清单、MV3 下 Readability/Turndown/GFM 最小抽取；独立网页夹具。 | Edge 侧载能对普通静态文章、SPA 已渲染正文、选区生成预览；原 B-043 力扣扩展 100% 通过。 |
| W-02 安全交接 | v2 session 分块/哈希/TTL/单次确认、站内接收并复用 HTML 导入预览。 | 匿名、伪 origin/端口/路径/tab、重放、分块缺失/乱序、篡改、超限、worker 重启均确定性失败；正文不进 URL/日志，草稿未改变。 |

## 9. B-043（V2.9.1）实现记录：通用剪藏替换力扣扩展，默认落私有笔记（2026-10-04）

按[当前通用剪藏说明](../browser-extension/README.md)完成扩展改造与站内接入；旧"仅力扣"popup 已被通用剪藏界面替代（同一扩展目录，无第二个扩展），站内 B-041 手动导入与既有文章/审核数据全部保留。

**抽取与 popup（自研移植）**：`browser-extension/shared/extract.js` 为 Readability+Turndown 思路的自研移植（上游 MarkDownload Apache-2.0 / Readability Apache-2.0 / Turndown MIT 仅作规则参考，未复制其代码或打包文件，无固定 commit 依赖；如需对齐上游以固定 commit 为准另行记录）。克隆 DOM 上评分取正文容器，支持 正文/选区/整页 三种范围；保留标题层级、列表、引用、代码围栏（语言）、表格、链接（去 utm 等跟踪参数）、图片 alt；`blob:/data:/file:` 与无 base 的相对图片一律标记"需手动上传"，占位为纯文本而非图片语法。抽取器明确不是安全过滤器。popup 显示来源、候选字段（待确认）、字数统计、图片警告与 Markdown 预览；无 tabs 权限或抽取失败时给出手动粘贴链接回退，不静默失败。

**v2 分块协议（kind=web）**：正文仅存 `chrome.storage.session`（2 MiB 上限、64 KiB/片、≤2 条待消费、5 分钟 TTL）；URL 只含 nonce/ext/kind。站内 get-meta → get-chunk(0..n-1) → 拼装验字节数 → ack；worker 每次复核消息类型/版本、完整 origin（协议+主机+端口）、/blog 路径、目标 tab、nonce、TTL 与一次性状态；ack/取消/过期均清理；并发双消费只成功一次。v1 力扣交接保留为只读兼容层（旧字段/限制不变）。

**站内接收**：`utils/webClipHandoff.ts`（fragment 解析、分块拉取、字节数校验、失败原因映射）；`BlogView.consumeExtensionClip` 按 v2 优先、v1 兼容的顺序消费，并按扩展 UI 的用户选择分派——`private_note`（默认）在"我的笔记"抽屉形成**未保存草稿**（`htmlToPlainMarkdown` 保守文本化，50,000 字上限，来源为"本人笔记（浏览器剪藏）"+ 来源链接），用户点"保存私有笔记"才调用真实登录态 API；`article_draft` 复用既有 `HtmlImportDialog`（外部 File + 初始 URL + 标题预填），经图片本地化与覆盖确认后才进本机草稿。未登录时清 fragment、toast 提示、不消费不保存。

**私有笔记来源与私有图片**：迁移 `0041_privatenote_web_clip_source`（`source_url` 可空 ≤2048 仅 HTTP(S)、`source_title` ≤200、`captured_at` 可空；外部来源与 `source_article` 互斥；服务器不因保存 URL 而抓取；存储前去 utm/spm/from/share/scene）、`0042_privatenote_private_images`（`PrivateNoteImage`：独立对象键、owner/workspace 绑定、note 可空）。新 API：`POST blog/notes/images/`（本地上传）、`POST blog/notes/images/fetch/`（复用既有远程抓取防护）、`GET blog/notes/images/<id>/`（认证读回，绝无 `/media/` 公开地址）、`POST blog/notes/<id>/images/bind/`（保存时绑定）；`cleanup_orphan_private_images` 清理 24h 未绑定孤儿。跨用户/跨 workspace 读取一律 404。搜索扩展到外部来源标题。

**旧功能退场**：popup 的力扣专用表单已移除；`legacy-clip-flow.js` 保留 v1 只读兼容；`LeetcodeImportDialog`、`link-preview` API、题目模板与既有数据未动。
