# 领域目录网页迁移设计 V2.8

> 状态：设计，尚未实现。对应 B-044。基于已落地的 [领域知识目录 V2.6](领域知识目录与系列博客设计V2.6.md)、[HTML 导入 V2.4](HTML导入Markdown博客设计V2.4.md)；不改变现有目录或文章。目标是把**具有标题层级和链接列表的网站目录页**迁成可编辑的领域学习路径，而不是无选择地复制整站文章。

## 1. 对参考页的观察与产品边界

[博客园参考页](https://www.cnblogs.com/littlehb/p/15393332.html)以页面标题为课程名，下面有六个“第 N 讲”章节；每章有若干知识点小标题，小标题下是有序文章链接。正文中还混有简短说明、分隔线和末尾的其他推荐链接。对这个页面，建议映射为：

```text
用户选择/创建的领域（例：算法）
└─ 页面标题 → 课程节点（第 1 级）
   ├─ 第 N 讲 → 章节节点（第 2 级）
   │  ├─ 知识点标题 → 知识点节点（第 3 级）
   │  │  └─ 文章链接 → 有来源的外链条目，或映射到本站已发布文章
   │  └─ 没有知识点标题的文章链接 → 直接挂到章节
   └─ 其余推荐链接 → 预览中单独标为“可能无关”，默认不选
```

上述层级来自页面实际可见的标题与链接顺序；导入器不预设“第一讲”这样的中文词，也不要求站点必须用 h3/h4。只要页面有相对稳定的标题层级和链接分组，就可使用通用解析器。遇到导航栏、广告、脚注、侧栏或结构歧义时，必须预览和人工调整，不能宣称所有网站 100% 自动识别。

**迁移有两种不同含义**：

| 模式 | 首轮支持 | 结果与权利边界 |
| --- | --- | --- |
| 目录与链接迁移 | 是 | 迁入用户选中的标题层级、链接标题、规范 URL、顺序和来源；点击外链仍回原站，不复制链接目标文章正文、题解、代码或图片。先进入本人私有目录工作版；公开需走目录审核。 |
| 外站文章全文迁移 | 仅本人作品/明确许可的内容可逐篇处理 | 使用已有 HTML→Markdown 预览与图片资源流程，作者核对并提交博客审核；目标文章真正发布后才映射到目录。第三方文章不能因 URL 可访问就被自动复制、改署名或公开。 |

参考页是第三方作者的学习目录。博客园[社区规范](https://about.cnblogs.com/guidelines)明确反对未经许可转载、搬运他人原创内容。因此此示例默认仅作**私有链接学习清单**；若要公开保留原目录的完整标题和编排，需核对作者许可与来源标注。系统中的公开目录审核须能看到“来自外站目录”的声明和原页链接，不把第三方目录包装成作者原创。用户重新独立整理自己的学习路径可以公开，但要保留引用来源并逐项检查。

## 2. 主要用户流程

1. 在“我的领域”选一个已有领域或创建新领域，点“从网页目录导入”。选择**网页 URL**或**本地保存的 HTML 文件**；后者不触发服务器访问外站，也是动态页面、访问失败或作者自己导出内容的回退方式。
2. 输入原页 URL（本地文件可另填来源 URL），系统只解析**这一页**，不跟随目录条目、分页、站内搜索或推荐链接批量抓取。显示候选正文容器和候选树。若是 HTML 文件，复用现有 HTML 导入的安全解析/清理理念，但采用专用“目录结构解析器”，不把整篇 HTML→Markdown 后再猜层级。
3. 预览采用三栏/窄屏两步：左侧原页标题层级与识别来源，中间可编辑的目标树，右侧逐项诊断（外站域名、重复 URL、无效链接、过深、超过容量、低置信度、版权来源）。用户可选择正文容器、移动节点、改名、取消条目、合并重复、决定每个链接“保留外链 / 映射本站文章 / 跳过”。不自动预选可疑的页脚、广告或其他课程链接。
4. 点击“应用到私有工作版”前显示差异：新增课程/章节/知识点数量、外链数量、被跳过项、将影响的现有顺序。必须选择“新建课程”或“合并到选中节点”；已有同源导入要显示更新/跳过/新增，而不是重建一套重复目录。请求带现有 `draft_version`，冲突 409 后要求重新预览。
5. 应用在单个数据库事务内完成：全部成功或全部回滚；原有节点、文章及已公开快照保持不变。作者可继续编辑私有目录。只有主动提交领域目录，管理员看到来源/权限说明并批准后，外链条目才可能公开。
6. 如果某个外链是作者本人已迁到本系统的文章，可在目录中搜索并映射到**同 workspace、当前已发布**的文章；作者身份必须经真实登录身份/许可核对，不能用可伪造的 `BlogArticle.author_name` 字符串证明所有权。映射前外链仍可用；映射确认后由内部文章引用替换该条目，原页 URL 留在导入审计记录。

页面应提供“下载这次导入的结构 JSON/CSV”和“撤销本次未公开导入”。公开过的目录不能直接抹掉历史快照，只能通过新工作版和再次审核进行更正。

## 3. 技术方案与数据取舍

### 3.1 输入层：通用 HTML，站点适配器只用于提高准确率

统一 `DirectorySource` 输入：`{kind: url|html_file, source_url?, content_bytes, fetched_at?, parser_version}`。先完成上传 HTML 的确定性解析；URL 模式使用单页安全取回器，固定上限 5 MiB、超时、文本 HTML MIME、无 Cookie/凭据、无任意重定向，不执行 JavaScript。复用 `remote_blog_image.py` 中的**公共 IP 校验、解析结果固定连接、HTTPS 证书校验**思路，但不能把图片抓取函数直接当 HTML 抓取函数使用；每个域名仍应检查站点条款/robots 和运营策略。不访问内网地址、IP literal、非标准端口或用户信息 URL；DNS rebinding、重定向、压缩炸弹和超时必须有专项测试。动态站点取不到正文时提示上传浏览器另存的 HTML；未来可由用户主动使用 B-043 扩展导出**目录结构快照**，不打开隐藏接口。

目录解析顺序：先从 `main/article`、通用正文容器、页面中“标题+链接密度较高的区域”产出候选，博客园容器选择器只是可选的 `CnblogsDirectoryAdapter`，不得成为解析器唯一入口；移除 `script/style/nav/aside/footer/form` 等明显噪音。按 DOM 文档顺序扫描 h1–h6、带标题的列表项、紧邻标题的 `<a>`，维护标题栈。将实际使用的标题级别规范化为相对深度，允许 h1→h3 跳级；无标题的链接挂到最近合法父节点。链接按来源 URL 解析相对路径，去跟踪参数，拒绝 `javascript:`/`data:`/`file:`、凭据和控制字符。正文里原站脚本、HTML、图片及代码一律不写入目录。

每个候选包含 `source_order`、`source_heading_level`、`target_depth`、`title`、`canonical_url`、`source_page_url`、`source_region`、`confidence`、`warnings[]`；分数只用于**提示**，不直接修改库。相同 URL 多次出现、不同 URL 同名、链接指向源站外以及链接标题与 URL 明显不符都交由预览决定。若只有视觉缩进、没有语义标题，可允许用户在预览中选“第一级标题选择器/目录根容器”，必要时手动整理。

不用模型做首要解析：确定性解析可复现、可单测、无需付费调用。以后可加“AI 建议分组”，但模型只返回候选树和理由，不直接提交；必须对真实样本测量相对规则解析的增益后再启用。

### 3.2 领域模型扩展：外链是引用，不是假文章

现有 `BlogCollection` + `BlogCollectionNode` + `BlogCollectionEntry` 保持原语义：`BlogCollectionEntry` 只能关联**同 workspace 已发布本站文章**，领域内文章唯一；树最多三级、100 节点/500 文章。不能创建空壳 `BlogArticle` 来代表外站链接，否则会混淆作者、审核和知识库索引。

建议新增：

| 结构 | 字段/作用 | 约束 |
| --- | --- | --- |
| `BlogCollectionExternalLink` | FK collection/node、`title`、`canonical_url`、`source_page_url`、`source_author`/站点、`position`、`import_batch`、时间戳 | 仅作为目录外链；不含目标正文；同领域规范 URL 默认唯一，重复出现需人工确认；同 workspace owner 才可编辑。 |
| `BlogCollectionImportBatch` | FK owner/collection、workspace、输入类型/来源 URL、`source_hash`、`parser_version`、选中候选 manifest JSON、状态、应用前后 `draft_version`、创建的 ID 清单、过期时间 | 预览只存清理后的结构，不存原始 HTML；所有读/写只给本人；未应用预览限时清理，日志不含外站正文。 |

限额仍以**内部文章 + 外链合计 ≤500**计算，节点 ≤100，超限时在预览要求拆成多个课程/领域，绝不静默截断。内部文章和外链需有**统一的混合排序**：新快照使用 `items: [{kind: article|external, id, node, position}]`，服务端一次校验每节点完整 ID 集合并原子重排。公开快照版本由 `collection-snapshot-v1` 升为 v2，读取端须兼容旧 v1（把旧 `entries` 视为 article items），避免旧目录突然消失。外链的公开读取只呈现标题、来源域名、URL 和外部图标；`target="_blank" rel="noopener noreferrer"`，绝不把外站内容放进本站阅读页、知识库或 AI 索引。删除/下架的内部文章仍按现有规则过滤，外链失效可标“原站不可用”，不能静默替换成其他 URL。

批量导入不是循环调用现有单个节点/条目 API（那样会触发限流、产生大量版本更新且失败半成品），而是新增单个应用服务：锁住 collection、检查 owner/workspace/`expected_version` 和容量、解析 manifest、创建节点/外链、分配混合顺序、`draft_version += 1` 一次提交。已有已发布快照、待审快照在本事务中不动；提交审核仍沿用 B-042。避免把目录页原作者写成当前用户的文章作者。

### 3.3 API 草案

| 方法/路径 | 行为 |
| --- | --- |
| `POST /api/agent/blog/collections/imports/preview/` | 登录用户上传 HTML 或给单页 URL；返回临时 `import_id`、识别树、置信度/警告与来源摘要；不改任何 collection。 |
| `PATCH /api/agent/blog/collections/imports/<uuid>/` | 仅 owner 编辑选择、目标位置、标题、映射动作；逐项验证，不接受任意 HTML。可用前端本地编辑后一次提交，但服务端仍需保存/复验最终 manifest。 |
| `POST /api/agent/blog/collections/<uuid>/imports/<uuid>/apply/` | owner + workspace + `expected_version`；事务应用到私有工作版，返回新版本、创建/跳过/冲突清单；重复请求幂等。 |
| `POST /api/agent/blog/collections/<uuid>/imports/<uuid>/undo/` | 仅未发布且导入后未再编辑时自动撤销新增对象；否则返回需人工处理的差异，不改已公开快照。 |
| `PATCH /api/agent/blog/collections/<uuid>/external-links/<id>/` | owner 改标题、位置/节点、规范 URL 或映射到本站已发布文章；仍要求 `expected_version`。 |

错误返回沿用项目 `detail/code`。状态包含 `previewed/applied/cancelled/expired`，同一 `source_hash` 重试不得复制节点；相同 URL 的新版本先显示差异。服务端不信任客户端传入的 owner、workspace、published 状态或 URL 已安全。`preview` 对普通用户限频，应用限大小/节点数/链接数；URL 抓取错误须区分 SSRF 拒绝、来源 403/404、HTML 无目录、解析低置信度。

## 4. 内容全文迁移的后续路径

当用户迁移**自己拥有或明确获授权**的文章时，建议先用原站官方导出/用户保存的 HTML 包。用户在预览中为每个外链选择本地文件，复用 B-040 的 HTML→Markdown、图片本地化、损失警告；每篇进入既有 Vditor 写作草稿，作者核对后按原有博客审批提交。当前 `POST /api/agent/blog/articles/` 会立即创建发布审批，不能拿它做后台静默批量私有文章。文章通过审批成为本站 published 后，再把对应外链映射为 `BlogCollectionEntry`；失败的文章仍保留来源链接，不产生假文章。

如果未来要“一次上传站点导出包、批量生成未提交文章草稿”，必须先设计真正的服务端私有文章草稿和稳定 owner FK、资源配额、批次事务/回滚；不能复用 `author_name` 字符串或绕过审核。第三方目录页的链接若指向其他作者或其他平台，默认只保留链接；不能因同一目录页把所有目标文章都视为同一作者的许可内容。

### 4.1 参考页文章实际情况与批量全文模式

参考目录中的前两个条目分别指向[“AcWing 785. 快速排序”](https://www.cnblogs.com/littlehb/p/15000855.html)和[“AcWing 786. 第 k 个数”](https://www.cnblogs.com/littlehb/p/15222977.html)等**独立博客园文章**，而不是目录页内隐藏的正文。它们包含 Markdown 可表示的标题、段落、代码，也可能有公式和跨域图片；第一篇的题目描述又链接到 AcWing。因此“目录作者的文章”和“其中引用的原题/图片”可能涉及不同权利人，不能给整篇内容打一个统一的“本人原创”标记。目录末尾还有指向其他平台的推荐链接，不能当成同一作者文章批量导入。

如果迁移者就是这些文章的权利人，或拿到覆盖复制、存储、修改、公开发布、图片和引用内容的许可，可以提供 **B-044D 授权批量全文迁移**：

1. 优先接收原站官方导出包/作者提供的 HTML 文件清单，依据目录 URL 与文件路径建立映射；只有许可允许的单页 URL 才逐项取回，不把“目录有链接”当成自动遍历授权。每篇独立记录 `source_url`、原作者、许可证明引用、内容哈希、转换版本和图片清单。
2. 每篇进入隔离的**未提交文章导入草稿**，执行 B-040 HTML→Markdown 与图片本地化，显示原文/转换结果差异及公式、代码围栏、图片失败清单。用户可逐篇或小批量确认；未确认、许可不足、图片缺失的文章不能自动提交审核。原始 HTML 不长期保留。
3. 批量任务逐篇状态为 `pending/converted/needs_review/submitted/approved/failed`，幂等键为 `(owner, source_url, source_hash)`；可暂停/恢复，失败不会回滚已经由作者确认的其他篇，但不会出现“目录已指向未发布文章”。每篇生成的内部文章须有稳定 owner FK 的私有草稿语义，待作者提交后走原有管理员审核，不能复用当前 `POST /api/agent/blog/articles/` 作为静默草稿接口。
4. 仅在文章获批准且 `published` 后，把对应目录外链原子替换为本站文章引用；保留来源审计和原站链接。若后续撤销许可或本站文章下架，公开目录立即按原有可见性规则过滤，管理员可回退到来源链接或移除条目。

这一批量全文阶段是**有前提的后续能力**，并非 B-044A/B 的默认行为。若没有权利证明，仍可迁入目录结构与外链，用户再用自己的理解重写博客。

## 5. 安全、撤销与失败恢复

- URL 模式一次只取输入目录页，禁止递归抓取、遍历同站、搜索引擎查询、登录态/Premium、反爬绕行或用浏览器 Cookie 代服务器请求。自有网站可走官方导出或用户提供文件。
- 原始 HTML 不持久化；解析候选使用纯文本/安全 URL，限长度、结构总量和 HTML 解析复杂度。前端只用 Vue 文本插值，不用未清理的 `v-html`；链接一律经协议/域名/重定向检查。
- 导入预览不改库中目录节点、文章、审批或公开快照；应用前显示明确差异与来源。事务失败 0 个新增对象，版本冲突 409；双击应用幂等。后台导入超时或 UI 关闭后可通过 batch 状态查询，不把未知结果当成功。
- 立即撤销仅删除本批新增且未再修改/未提交审核的节点与外链；如果已经编辑或公开，必须在新私有工作版中回退并重新提交审核，保留历史审计。清理过期 preview batch 和无引用临时资源；不删除用户原本已有文章。
