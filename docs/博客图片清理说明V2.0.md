# 博客图片清理说明 V2.0

## 当前行为

- 删除文章仍需管理员审批。审批成功且数据库事务提交后，系统收集该文章正文、封面及所有修订中引用的本站 `/media/blog/<随机文件名>` 图片。
- 删除前重新检查现存文章、修订、私有笔记、领域目录、评论、知识文档和博客 Agent 消息中的图片引用。只有没有剩余引用的图片才从 `blog_media` 存储中删除；共享图片保留。私有笔记图片使用另一套存储，不在此流程内。
- 文件删除失败不会撤销已经提交的文章删除；服务端记错误日志，可再运行下方孤儿扫描。上传后从未放入文章的图片、编辑时提前移除的旧图片，也需通过孤儿扫描处理。

## 历史和废弃图片

先在后端环境执行只读预览：

```powershell
python manage.py prune_blog_media --older-than-days 30
```

核对预览、媒体备份和存储配置后，再由管理员执行：

```powershell
python manage.py prune_blog_media --older-than-days 30 --apply
```

命令仅检查 `blog/` 下由系统生成的 UUID 图片名；默认只预览，跳过修改时间不可读取的对象及 30 天内的新上传，并在删除前再次检查引用。该命令**没有在现有真实媒体库执行**。生产环境建议在备份恢复演练和真实 Bucket 验收后定期人工运行；不要对整个媒体目录执行通用递归删除。

## 边界

引用判断覆盖本站数据库中用于展示内容的字段；站外网页、导出的 Markdown 或手工复制的外部链接无法由本站识别。删除图片会使这些站外副本失效，因此清理前需保留可恢复备份。文章删除和对象存储删除无法组成同一个原子事务；存储失败时日志和孤儿扫描负责后续补救。
