# 托盘工具长截屏缺陷分析与 Luna 实现提示词

检查日期：2026-10-21。对象：`tools/screenshot-tray`。

本轮只检查代码、读取本机日志并执行内存合成图实验，没有修改工具实现，也没有操作用户的桌面窗口。以下区分了已复现问题和代码审查发现的风险，不能据此断言每次实机失败都由同一个原因造成。

## 一、主要结论与证据

### P0：高 DPI 抓帧被再次缩小，长截图输入本身就不正确（已复现）

位置：`ui/scroll_capture.py:475-505`，普通截图的 `ui/overlay_selector.py:173-207` 也有同类问题。

当前按物理像素计算结果画布，却直接用 `QPainter.drawImage(x, y, piece)` 绘制仍带原始 DPR 的图片。`QImage.copy()` 保留 DPR，绘制时图片会按设备无关尺寸呈现。

实测：创建 600×450 的红色图片，DPR=1.5，复制后画到 DPR=1 的 600×450 蓝色画布。只有左上 400×300 被填成红色，右侧和底部保持蓝色。将复制图片的 DPR 规范到 1 后，右下角也正确变为红色。

长截图的结果画布还没有调用 `fill()`，未覆盖区域内容不确定，会污染帧间差分与接缝匹配。普通截图虽然填了透明色，但仍有缩小和空白问题。

本机日志显示多个会话采用了 150% 缩放，例如逻辑选区 832×335 → 抓帧 1248×502；2026-10-21 19:43 会话第二帧被拒绝，最佳候选差分 54.77，阈值为 14。日志支持这一排查方向，但没有原始失败帧，尚不能证明该次失败的全部原因。

**方案：**明确“全局逻辑坐标、屏幕局部逻辑坐标、输出物理像素坐标”的边界。裁剪后进入像素处理的图片统一 DPR=1，输出画布先初始化。不要在绘制时再次进行隐式 DPI 缩放。

### P1：1024 像素匹配上限排除了真实接缝（已复现）

位置：`services/stitcher.py:49,394`。

1500 像素高视口向下滚动 100 像素，真实重叠是 1400；算法只搜索最多 1024，因此不可能找到真实接缝。用逐行随机颜色的确定性图片复现：当前抛 `no_overlap`，正确总高应为 1600。对照实验：500 高视口滚动 100，正确输出 600 高。

**方案：**根据相邻原始帧高度覆盖全部有效重叠范围，使用粗到细搜索、缓存和向量化控制成本，不能仅把 1024 改成另一个固定上限。

### P1：一维剖面丢失横向内容，精扫也不是二维像素复核（已复现信息丢失）

位置：`services/stitcher.py:182-233,402-405`。

每行最后只剩非背景像素的平均颜色偏差 `d/c`，横向位置和最终评分中的像素数量信息丢失。白底图左侧的 80 像素黑条，与移到右侧的同宽黑条，会生成完全相同的剖面。文字、表格和重复列表因此可能得到大量近似并列候选，被保守拒绝，也可能选错。当前所谓“全分辨率精扫”仍然比较这一维剖面。

**方案：**一维剖面只用于提名候选；最终按多个横向分区的二维边缘/灰度/RGB 特征复核，包含足够空间覆盖的有效内容证据。歧义判断应比较不同位移峰，而非把同一个峰的相邻像素全部视为独立解释。真正不可判定时保留结果并提示恢复重叠。

### P1：重试后的基线会吞掉已经恢复的有效画面（已复现）

位置：`ui/scroll_capture.py:283-286,309-328,549-557`。

重试清空 `collected_frame`，下一帧被同时记为“当前基线”和“已采集帧”，但旧画布非空时不调用拼接。之后画面不动，会一直走重复分支；用户明明已经回到可恢复重叠的位置，仍不会续接。

实测：已有 500 高首帧，重试后提交相对首帧下移 100 的有效画面六次，结果仍是 1 帧、500 高；同样两帧直接交给 Stitcher 可正确输出 600 高。

**方案：**独立保留最后成功采集的原始帧和匹配锚点；重试只重置稳定计数与瞬时变化基线，恢复后的首个稳定画面必须尝试与最后成功帧对齐。提供“向上滚动，恢复与上一帧的重叠”的具体提示。

### P1：混合 DPI 跨屏缺少统一输出坐标系（代码确认，需多屏实机验收）

两处合成都用“各片段全局偏移 × 该片段自己的 DPR”决定输出位置，不同片段采用不同标尺，会产生间隙、覆盖或上下错位。单独将图片 DPR 改为 1 无法解决这个问题。

**方案：**选区会话固定一个输出 DPR，所有片段位置和尺寸都按同一标尺计算，源图按实际 DPR 裁剪，再显式缩放到目标矩形。共享给普通截图和长截图。需声明混合缩放会重采样；如暂时无法可靠实现，应明确限制长截图为单屏，不能静默输出错误图。

### P2：采集、交互和固定元素处理仍有风险（代码审查）

- 无界帧队列、控制命令与大图同队列：处理落后时，暂停/取消仍可能继续消费旧帧，`join(timeout=1)` 后便释放控制器，存在延迟结果、线程和对象生命周期风险。日志里也出现过取消后继续输出拼接记录，但该日志来自旧运行版本，当前版本仍需独立验证。
- 完成直接请求已有结果，没有保证最后一个稳定画面被处理；连续滚动时又可能长期达不到稳定判据，最后一段容易遗漏。
- “画面变化=真实滚动”“滚动后静止=疑似到底”都不成立。动画可触发变化，用户中途停手也会被提示到底。没有滚动尝试证据时应显示“画面暂无变化”。
- 控制窗 `show_near()` 只做左右放置和屏内夹取，大选区时可能落回采集区；控件只在自己的 `keyPressEvent` 处理 Esc，目标应用有焦点时无法保证结束会话。
- `_profile_diff()` 先删除空白行再跳过前 L 个差分值，实际跳的是“证据行”，并非注释所述的图像顶部 L 像素。固定元素掩码与接缝绘制也没有统一，新帧整幅覆盖重叠区可能把固定栏反复带入长图。
- 20M 像素限制意味着 3000 像素宽时总高只有约 6666，不能只向用户宣传 30000；首帧分支也没有完整执行像素/高度限制。

**方案：**有界采集缓存和独立控制通道，显式状态机及会话编号；按实际位移确认滚动；结束时做有限等待和末帧处理；控制窗避让/抓帧排除、会话级 Esc；固定区域按真实二维坐标处理，最后根据位移仅追加新的页面内容。保留帧数/高度/像素上限并准确展示原因。

## 二、建议实施顺序

1. 先修抓帧 DPR、初始化和统一坐标，加入实际调用合成函数的回归测试，确认单帧像素正确。
2. 修相邻帧匹配：覆盖真实重叠、二维复核、方向与重复内容判断。
3. 修重试、末帧、队列和线程生命周期。
4. 完成控制窗、Esc、固定元素和混合 DPI 实机验收，更新 README。

不要只提高 `_DIFF_ACCEPT` 或继续堆剖面阈值；这会掩盖输入问题并提高错拼风险。

## 三、可以直接复制给 Luna 的提示词

```text
请直接修复本仓库 tools/screenshot-tray 的长截屏功能，并完成回归验证。开始前读取适用的 AGENTS.md、tools/screenshot-tray/README.md 和 docs/长截屏缺陷分析与Luna修复提示词.md。分析文档已通过当前 .venv 中 PyQt6 6.7.1 做过内存合成图验证，但尚未完成桌面实机验收；请独立复核后实施。

工作范围：优先修改 tools/screenshot-tray，必要时更新它的依赖、测试和文档。仓库有大量用户未提交改动，请保留；不要重置、清理或覆盖无关文件，不要提交或推送。保持普通截图、发博客、存本地、OCR 的现有接口和动作流程。使用项目根 .venv，不全局安装包。若二维匹配需要 numpy/OpenCV，可评估并采用必要依赖，说明收益和成本；不要为了无第三方依赖继续堆低可靠性算法。

先实现并验证 P0，再推进后面的阶段。不要只修改匹配阈值或 README 就宣称完成。

1. 修复实际抓帧/合成链路的 DPI 问题。
   - ui/scroll_capture.py 的 _grab_selection 与 ui/overlay_selector.py 的 _compose 都存在：物理像素画布直接 drawImage 带 DPR 的 QImage，导致隐式缩小。600×450、DPR=1.5 的图片当前只画出 400×300，已复现。
   - 将逻辑坐标、源物理像素、输出像素映射明确分开。裁剪后的处理图片及输出 QImage 统一 DPR=1，所有画布先 fill，并处理空帧、尺寸不符和分配失败。
   - 提取可测试的共享合成函数，覆盖两处实际调用链。混合 DPI 跨屏选区固定一个输出 DPR，全部片段的偏移和尺寸使用同一标尺，源图按本屏 DPR 裁剪，再显式重采样到目标矩形；共享边界用一致的边界取整规则，避免缝隙和重叠。不得继续使用各片段自己的 DPR 计算全局输出偏移。

2. 修复匹配与拼接。
   - 不再用固定 1024 像素上限截断可能的重叠。1500 高帧向下滚动 100，必须识别 1400 重叠并输出 1600 高。
   - 当前每行 d/c 剖面丢失横向位置，左右黑条能得到完全相同的剖面。可保留它做粗候选，最终必须做二维空间内容复核，使用多个横向分区及有效内容覆盖，区分真正重复内容与空白巧合。
   - 正确区分静止、微滚、向下、向上、水平偏移、无重叠和歧义。纯向下长截图可在向上滚动时进入恢复/等待状态，不必强制支持任意二维拼接，但不得向下误追加。微滚暂不追加时仍须保留成功锚点以便累计，不能丢失内容。
   - 匹配锚点优先使用最后成功的原始帧，避免合成长图被固定元素/接缝污染后用于下一轮匹配。记录位移及输出覆盖范围，仅追加真正新增的内容；无可靠证据时保留已拼结果并清晰提示。
   - 固定页头/页脚、侧栏及局部动画按二维坐标识别和屏蔽；不得先压缩掉空白行再把证据行数量当作像素高度裁掉。匹配掩码、源图裁剪及接缝合成必须一致，不能只让匹配通过而把固定栏重复画入正文。无法可靠处理的复杂固定元素应明确给出避开选区的提示，不要承诺任意页面均可拼接。

3. 修复采集状态、恢复和结束。
   - 明确 idle/capturing/paused/recovering/finishing/cancelled 等状态或等价实现，成功采集帧、轮询基线、稳定计数互相独立。
   - 重试必须保留最后成功原始帧。恢复后首个稳定画面就尝试接回该锚点，不能标记为“已采集”后不追加。测试：已有500高首帧，reset后输入相对下移100的稳定帧，正确结果600高。
   - 使用有界采集缓存和独立优先控制通道/停止标志，避免后台落后时堆积整幅 QImage。不能为限队列随意丢弃唯一能保持重叠的中间帧；队列策略需兼顾速度和重叠不足时的明确恢复提示。
   - 暂停/重试清理旧采集任务；给帧和信号添加会话/代际校验，忽略过期事件。取消后不得继续拼接或回调已释放 UI，工作线程结束后再释放对象，GUI 不要长时间阻塞。
   - 完成时保证最后可用稳定帧被处理，避免用户滚动后立刻点完成而漏尾。可以有有限时长的 finishing 等待，不能无限等待动画稳定。连续滚动时采用能保持可靠重叠的采集策略，或者及时提示用户分段停顿，不要长期无反馈。
   - 仅画面变化不能证明滚动；仅停手不能证明到底。无滚动尝试证据时显示“画面暂无变化”，不要反复误报底部。

4. 修复交互和资源限制。
   - 控制窗不能污染选区；大选区放不下时采用可验证的抓屏排除/临时隐藏等方案，并保持控制窗可操作。装饰边框保持鼠标穿透、只画在选区外。
   - Esc 在目标应用有焦点时也应完成当前会话，按会话注册并可靠注销，保留关闭窗口=取消的语义。
   - 帧数、总高和总像素限制对首帧及后续帧均有效；准确告知触发原因，保留已拼部分。避免每次传输完整长图导致大量内存驻留，预览使用缩略图或等价优化。

5. 测试和验收。
   - 建立离线可重复的合成图回归：100%/125%/150%/200% DPR；混合 DPI 两屏和负屏幕坐标；像素坐标正确、没有未初始化区域和二次缩放。测试共享合成函数并确认两处生产入口确实调用它。
   - 有唯一内容标记的页面按已知位移切片，检查最终高度和像素接缝；覆盖小步/大步、1500高视口滚100、稀疏白底、深色、彩色图片、不同横向布局但相同剖面、重复表格、静止噪声和局部动画。
   - 覆盖重试第一张有效稳定帧、暂停后旧队列、取消/完成竞态、末帧、资源上限；不可匹配时明确失败并保留有效内容，不能静默错拼。
   - 使用带编号行和末尾标记的可控测试页做桌面人工验收：Edge/Chrome 普通长文、内部滚动容器、固定页头场景，滚动后检查编号连续、末尾标记完整、没有重复导航或工具窗。纯静态拼接测试不等于完成桌面验收。
   - 本机日志位于 %APPDATA%/BlogScreenshotTool/logs/tray.log，可用于对照；日志增加帧号、DPR/尺寸、位移、匹配置信度、拒绝原因、队列深度及状态转换。调试原始帧只在显式开启诊断时保存，默认不落盘用户屏幕内容。

最终交付：实际代码、回归测试及结果、更新后的 README、修改文件清单、仍存在的边界和确实完成的实机验收项。没有运行的测试必须明确标注，不要写“全部通过”。若环境无法操作桌面，请完成可运行的代码和离线测试，并给出精确人工验收步骤。
```
