# I-009 权限隔离与工具边界核查

日期：2026-10-23。范围为 Agent API 的文档、会话、检索、笔记、图片、文章发布、任务查询和内置 MCP 工具。以下矩阵按 `AGENT_SECURITY_ENFORCED=True` 的服务端行为填写；本地关闭强制安全时，开发用 `X-Role` 可绕过角色门槛，不能用该模式作生产权限证明。

## 资源 × 动作 × 角色 × workspace

## 确认并修复的缺口

- **B-065**：工具列表的默认注册逻辑曾重新启用被管理员关闭的 `web_search`。新增请求级失败用例后移除该运行时覆写；迁移中既有启用状态不变。
- **B-066**：`safe_database_stats` 曾返回全库聚合数。执行器现在要求 workspace 上下文，所有 HTTP、聊天及审批入口都传服务端确认的 workspace；没有上下文时不做统计。
- **B-067**：会话读取缺少角色门槛。隔离库中构造遗留 `owner_username="anonymous"` 会话后，未登录请求原可读取；列表与详情现要求 operator，仍保留 owner/workspace 过滤。未发现或读取真实生产库中的此类记录。

隔离测试还确认：JWT 角色降级和账号停用会在下一次请求生效；`X-Role`/`X-Workspace` 不覆盖数据库身份；伪造外空间工具/审批 ID 得 404；审批等待期间禁用工具后，审批执行标记失败且不调用工具。网页搜索返回的恶意文字尝试要求第二个工具及发布私有文章时，当前路径只有原先获准的网页搜索一次工具调用，没有新增审批或发布。检索片段要求执行统计及发布时，当前无模型 RAG 路径只记录 `knowledge_search`，未调用 MCP 或审批。**这只验证当前路由和 mock 外部结果不能触发第二次工具执行**，不证明真实模型不会在回答正文里复述恶意内容，也不替代全面提示注入评测。

工具 `permission_scope` 目前是注册元数据，实际执行边界由服务器角色、workspace、`is_enabled`、`requires_approval` 与 `LocalMCPToolRunner` 的显式工具分派共同决定。`MCPTool.name` 仍是全局唯一：不同 workspace 不能各自注册同名工具。这是多空间配置能力限制，当前测试未证明它造成越权；若产品需要每空间独立同名工具，应单独设计迁移与兼容方案。

## 验证范围与剩余项

本轮只使用隔离测试数据库和测试 JWT，没有改真实用户角色或真实工具配置。基线强制安全相关测试 65/65；新增的三个缺口均先由失败用例复现，再修复。最终相关回归与静态检查结果见改进表 I-009 实施记录。

待验证：部署环境的真实 JWT/反向代理/共享缓存配置，历史匿名会话存量，跨实例权限撤销时间，真实远程网页与检索材料的提示注入样本，以及外部 MCP 服务（本次只核查仓库内 `LocalMCPToolRunner`）。通过这些验证前，不把本报告当作全系统安全审计结论。
