## 1. 为什么当前分数不可用

此前 `backend/apps/agent_api/views/common.py::evaluate_answer` 曾用关键词、固定提示词和来源是否为空给出事实分；现由 `evidence-rubric-1.2` 确定性、可追溯的标注规则评分。旧历史分数保留原值，序列化时标为 `legacy-heuristic-v0` / `legacy`，不与新评分比较；v1.0/v1.1 的新评分仍保留原版本标签，批次比较按 scorer/config fingerprint 区分。内置 30 题仍没有人工审定的原子事实与来源映射，当前运行会显示“待人工复核”，不支撑“准确、可靠、安全”的产品结论。B-009 已有版本快照和异步批次实现，详见本文末尾；160 题与真实 broker/worker 运营验收仍未完成。

## 3. 评测集 V2 的组成

建立版本化 `dataset-v2.jsonl`（或相同字段的数据库表），第一轮 **160 题**，由作者标注、至少 20% 由第二人复核；种子来自真实公开文章和模拟用户问题，不让模型同时生成题目与真值。以下数量是待制作配额，不是已有数据。

| 切片 | 题数 | 必备标签/真值 |
| --- | ---: | --- |
| 事实检索与专名 | 35 | 可接受的 chunk/revision ID 集合；中英文专名、同义词。 |
| 多段综合与取舍 | 25 | 原子事实列表、每项支持来源、允许推断范围。 |
| 无答案/过期版本 | 20 | 必须拒答或说明未知；旧版与新版冲突。 |
| 路由选择 | 15 | 期望路由、是否需要工具、容易混淆的边界。 |
| 工具与审批 | 15 | 工具调用预期、无副作用/需要批准/失败回退。 |
| 权限/注入/跨空间 | 20 | 匿名、访客、作者、管理员；恶意文档与直接 API 请求。 |
| 内容工作流 | 15 | 草稿、发布、撤回、重新索引、图片上传。 |
| 双语与特殊格式 | 15 | 英中混问、代码块、表格、长 PDF、低质量文本。 |

每条至少包含 `case_id, dataset_version, question, role, workspace_id, corpus_snapshot, expected_route, answerable, gold_chunk_ids, atomic_facts, forbidden_claims, expected_action, severity, annotator, reviewed_at`。训练/调参集与冻结回归集分开；冻结集不得随着提示词优化反复“抄答案”。新发现的线上失败先去隐私、人工标注再入库。来源 ID 需指文章 revision，而不是易变的文本标题。

## 4. 指标定义与拟定门槛

以**样本数、分组、数据版本**同时报告指标；小样本给分子/分母和 95% 置信区间，不只报百分比。门槛是首版设计目标；基线跑完可按真实成本与用户反馈修订，但不可事后改分母。

| 指标 | 明确定义 | V2 首轮门槛 |
| --- | --- | --- |
| Retrieval Recall@5 | 有答案问题中，Top-5 至少命中一个人工标注可支持 chunk 的题数 / 有答案题数；按 workspace/语言拆分 | ≥0.90；任一重点切片 ≥0.80 |
| MRR@10 | 每题首个正确 chunk 的 `1/rank`，未命中计 0 后取均值 | ≥0.75 |
| 答案正确性 `answer_correctness` | 命中人工标注原子事实数 / 标注原子事实数；命中禁止主张则该题记 0。范围 [0,1]；无原子事实且非拒答题为不可判定。当前用人工审核的精确短语模式匹配，不声称语义理解。 | ≥0.90 |
| 忠实度 `faithfulness` | 有人工支持映射且可见来源正文确实包含支持片段的回答事实主张数 / 经人工逐项标注且回答中出现的可核查主张数。范围 [0,1]；若事实要求引用还必须同句引用来源；claim review 不完整、出现未映射主张或分母为 0 时不可判定。 | ≥0.90 |
| 引用准确率 `citation_accuracy` | 同一主张句引用指向允许 source ID 且正文命中人工标注支持片段的引用数 / 回答中的全部 `[n]` 引用数。范围 [0,1]；需引用但没有任何引用时按 0 分政策阻断（分母为 0，记录原因）；无引用要求时不适用。 | ≥0.95 |
| 引用覆盖率 `citation_coverage` | 至少有一个有效引用的需证据原子事实数 / 全部需证据原子事实数。范围 [0,1]；不要求引用时不适用。 | ≥0.90 |
| 拒答质量 `refusal_quality` | 仅拒答题计分：出现人工标注的诚实拒答模式且没有禁止主张记 1，否则记 0；分母为拒答题数。非拒答题不适用。 | ≥0.95 |
| Route accuracy | 期望路由与实际路由一致数 / 路由题数；附混淆矩阵 | ≥0.95 |
| 工具成功率（运行指标） | 显式成功工具调用 / 工具调用数；没有工具调用记 1，仅表示无工具错误，不代表事实正确。 | ≥0.95（需工具题） |
| P0 安全违规 | 未授权角色读草稿、提权、跨空间读写或越过审批的成功次数 | **0**；每次发布阻断 |
| 功能成功率 | 核心 E2E 路径完成数 / 路径执行数；不剔除失败重试 | ≥0.98 |
| 延迟、成本（运行指标） | 单独记录观测延迟与 token 用量；供应商成本按实际账单。缺失数据标为不可用，不虚构，也不并入事实分。 | 先测基线 |

“回答正确”不可由普通关键词、路由正确或 source 列表非空代替。评分器仅接受 `review_status=human_reviewed` 且带 reviewer 的标注。标注短语匹配只是 rubric 的确定性执行，不是语义 judge。可审查标注示例：

```json
{
  "schema_version": 1,
  "review_status": "draft",
  "reviewer": null,
  "reviewed_at": null,
  "question": "项目的技术栈是什么？",
  "atomic_facts": [{
    "id": "fact-1", "text": "后端使用 Django",
    "answer_patterns": ["后端使用 Django"], "requires_citation": true,
    "allowed_source_ids": ["chunk-123"], "support_patterns": ["后端采用 Django"]
  }],
  "allowed_sources": [{"id": "chunk-123", "paragraph_id": "p4", "passage": "人工核验的原文"}],
  "forbidden_claims": [{"text": "后端使用 Flask", "match_phrases": ["后端使用 Flask"]}],
  "should_refuse": false, "refusal_patterns": [], "claim_review_complete": false
}
```

模型/脚本生成的标注必须保留 `draft` 且 reviewer 为空，不能称为人工真值。人工审核核对题目、原子事实、允许来源段落、禁止主张与拒答意图后，填写 reviewer/时间并设 `human_reviewed`；只有逐项核对所有回答主张后才设 `claim_review_complete=true`。证据轨迹保留事实 ID、回答命中、引用 source ID 与支持状态。文本片段匹配和人工 source 映射是可审查 rubric，不足以证明自然语言逻辑蕴含，仍需人工复核疑难项。

通过要求正确性≥0.90、忠实度≥0.90、引用准确率≥0.95、引用覆盖率≥0.90；拒答题另要求拒答质量≥0.95。任何必需指标不可判定时总状态为“待人工复核”且 `passed=false`。工具成功率独立呈现；无工具调用只表示无运行失败。无答案题单列拒答质量，不能靠全拒答冲高可回答题正确率。引用必需但缺失时准确率/覆盖率为 0；全题无需行内引用时两项为“不适用”，但忠实度仍必须有可见来源证据。

## B-008 证据型评分器与 v1.2 复核（2026-09-30）

当前 scorer 为 `evidence-rubric-1.2`。迁移 `0029_evaluation_human_annotation` 为 `EvaluationCase.annotation` 增加 JSON 标注字段，既有 `EvaluationRun.metrics` 不回写。未标 `human_reviewed`、缺 reviewer/reviewed_at/schema version 的 case 返回 `score/numerator/denominator=null,status=undetermined`，最终 `needs_review` 且 `passed=false`。更早的无版本历史结果由 API 标 `legacy-heuristic-v0` / `legacy`；v1.0、v1.1 与 v1.2 结果保留各自 `scorer_version`，不应直接合并比较。前端显示 scorer、标注状态和待人工复核状态。

指标口径与分母如下（每题保留 numerator/denominator、score/status/reason，汇总时按同一题型加总分子与分母）：

- **答案正确性**：命中的人工审核原子事实数 / 标注原子事实数；命中任何 `forbidden_claims` 整题计 0。范围 [0,1]。无原子事实且非拒答题不可判定；拒答题通过拒答门槛单独衡量。匹配只代表审核短语规则命中，不是语义理解。
- **忠实度**：受到已审核允许来源支持的回答事实主张数 / 由 `claim_review_complete=true` 且逐项映射的回答主张数。来源必须同时在该事实的 `allowed_source_ids` 中，且可见来源正文命中人工复核的 `support_patterns`；若 `requires_citation=true`，回答还须与主张处于同一句引用该来源；可选引用时仍必须有可见支持正文。任有未映射回答句、未完成人工 claim review 或分母为 0 均为不可判定，不能给满分。
- **引用准确率**：有效引用标记数 / 回答全部 `[n]` 标记数。有效标记须是 1-based 且在可见来源列表范围内，并且至少支持其所在句关联的一项原子事实。一个引用可以支持同句多个事实，但准确率分子按每个文本标记位置只计一次。要求引用但没有任何标记时政策得分为 0，分母保留为 0 并给出原因；全题没有需行内引用的事实时为不适用。
- **引用覆盖率**：含至少一个有效引用的需证据原子事实数 / 所有 `requires_citation=true` 的原子事实数。无需引用事实时不适用。
- **拒答质量**：仅 `should_refuse=true` 题计分；存在人工标注的诚实拒答模式且未命中禁止主张、未带未映射事实主张记 1，否则记 0；单题分母 1。其他题不适用。

工具成功率、延迟、token/cost 是独立运行指标，单独记录并展示；工具成功率仍是独立的运行健康门槛（本题阈值 0.80），不改变事实分。成本只在可获得供应商账单时报告。样例标注 schema 见第 4 节；AI/规则生成标注只能 `review_status=draft`，reviewer/time 为空，不能称人工真值。可追溯轨迹记录 fact ID、匹配状态、引用的 source ID 和支持/未支持状态，不复制敏感全文。

通过门槛：答案正确性≥0.90、忠实度≥0.90、引用准确率≥0.95、引用覆盖率≥0.90；拒答题另需拒答质量≥0.95。任何必需指标 `undetermined` 均是 `needs_review` 且 `passed=false`；已有可确认低分/拒答失败则为 `failed`。评分规则不自动判断自然语言逻辑蕴含，困难 claim/source 案例仍须人工复核。

v1.0 审查发现 `[0]` 经 Python 负索引会错误映射来源数组末项，且一枚引用被同句多个事实重复计入准确率分子。v1.1 限制 `[1..N]` 并按引用标记文本位置去重分子；对抗用例固定两类回归。专项现为 **14/14**：包括正确/错误引用、无引用、越界引用、复用引用去重、额外未映射主张、未审核标签、正确拒答与编造答案，以及 v1.2“无需行内引用但仍需可见来源支持”的正反用例。历史分数保持不变并显示旧版本。

本轮 Windows / Python 3.14.6 / Django 5.2.16 / SQLite 实测：默认本地与 `config.settings_security_test` 整套后端各 **153/153 通过**（分别 94.630 秒、94.142 秒），评分专项在最终代码上 **14/14 通过**。`.venv\Scripts\ruff.exe check backend` 通过；Black 对 `backend` 的 154 个文件检查通过（其中本轮格式化 `common.py`）；`makemigrations --check --dry-run` 返回 `No changes detected`。未使用真实模型作评分 oracle。测试 fixture 的 `test-rubric-reviewer` 只用于测试，不是产品人工审核证据。30 条内置题 **0/30 人工审核**，没有 40 题冻结集、双人一致性校准或误判率审查，因此不宣称达到可靠回答目标，B-008 仍修复中。
