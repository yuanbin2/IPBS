# I-021：当前架构与技术取舍

日期：2026-10-24。此文是源码与 `docker-compose.yml` 的架构决策记录，不是生产运行验收。总图见[架构概览](architecture.md)；AI 子决策沿用 [I-007](I-007-LangGraph工作流决策.md)。

## 边界与职责

| 边界 | 已实现的职责与事实来源 | 尚不能据此断言 |
| --- | --- | --- |
| Vue 3 / Vite | `frontend/src/views/` 和 `features/` 承载交互；API 客户端请求 Django，问答视图消费 SSE、按 `run_id` 查询结果；构建产物由 Nginx 或本地 Django 提供。单篇公开文章的直达 HTML 由 Django 按请求补元信息与摘要，Vue 接管正文。 | 不是全站 SSR；浏览器展示不承担最终权限判断。 |
| Django / DRF | `backend/apps/agent_api/api_urls/` 与 `views/` 负责输入校验、用户角色与 workspace 判定、业务状态、审批、问答执行和结果持久化；`backend/config/urls.py` 提供 API、公开页面与媒体入口。 | 模块化单体内的 View/服务拆分不等于多个独立服务。 |
| PostgreSQL / pgvector | `models/` 与迁移保存会话、`AgentRun`、文档/切片/入库任务、文章/修订/审批；生产检索经 `services/vector_store.py` 的 pgvector，按 workspace、有效入库代际和 embedding 空间过滤。 | 本地 SQLite 的 `EmbeddingRecord` JSON 回退不代表 pgvector 性能或质量。 |
| 文件存储 | 文档 `Document.source_file` 与博客媒体走 Django storage；公开博客图片经受控代理；私有笔记图使用公开 `MEDIA_ROOT` 外的独立 storage。Compose 当前挂载媒体卷，`BLOG_MEDIA_STORAGE` 可配置博客媒体后端。 | 数据库事务与文件存储不是同一原子事务；实际对象存储、备份恢复需单独验收。 |
| RabbitMQ / Celery | `DocumentIngestionJob` 是持久 outbox 和任务状态源；Celery worker 执行解析、向量化及评测，beat 周期性重投到期入库任务。 | broker 接收消息不等于处理完成；问答与审批当前不由 Celery 执行。 |
| Redis | 非本地模式用于 Django 缓存（如部分限频）与 Celery 结果后端；本地模式为 LocMem/同步任务。 | 缓存或 Celery 结果不是文档、聊天和审批的权威持久数据。 |
| AI 工作流 | `MultiAgentSupervisor` 按规则分发；RAG 使用有限 LangGraph 图串联查询分析、检索、相关性判定、最多一次改写和生成。生成、查询扩展/改写等步骤可能调用模型，回答引用来自本轮检索。 | 规则路由不是自主多 Agent 协作；`AgentRun` 持久化不是图 checkpoint/跨进程节点恢复。 |

Compose 运行形态：前端 Nginx 仅绑定主机 `127.0.0.1:${NGINX_PORT}`，backend、PostgreSQL、Redis、RabbitMQ、worker、beat 位于内部网络；生产 TLS 终止依赖外部代理与配置。`BLOG_LOCAL_MODE=true` 采用 SQLite、LocMem 和 eager Celery，仅供本地开发/演示。实际部署入口、版本与环境要求见[部署说明](deployment.md)。

## 三条端到端数据流

### 1. 问答（当前 Web 主入口）

1. `AgentChatView.vue` 发送 `POST /api/agent/chat/stream/`，带 `run_id`；服务端 `require_roles(OPERATOR)`，按用户、workspace 和会话 owner 校验。`claim_run` 对相同请求指纹复用 UUID，在同一数据库事务创建 `Conversation`、用户 `Message`、`AgentRun(pending)`；同 ID 不同请求返回 409。
2. 状态转为 `running` 后，Django 请求内调用 `MultiAgentSupervisor`。规则决定直接回答、私有知识 RAG、博客等路径；RAG 从当前 workspace 的有效资料检索，再由模型生成。SSE 发 `run`、`progress`、`answer_delta`/`answer_snapshot`、最终 `response` 和 `done`；部分路径仅有最终正文。来源、模型用量和阶段耗时随结果保存。
3. 成功时 `AgentRun(succeeded)`、助手 `Message`、观察记录在事务中一起落库，再返回最终结果。前端可用 `GET /api/agent/chat/runs/<run_id>/` 找回断线结果；查询按用户和 workspace 限定。
4. 执行异常/超时写 `failed` 与安全错误码；取消接口对 pending 立即标记 `cancelled`，对 running 先写 `cancel_requested`、在步骤边界协作停止。停止读取 SSE 只是断开接收，服务端迭代器尽力继续执行和保存。遗留的 pending/running 在有权限的后续查询中按超时阈值识别并转为失败；没有图 checkpoint 恢复。不得把缺少本轮资料的回答说成有来源。

代码：`frontend/src/views/AgentChatView.vue`、`backend/apps/agent_api/views/chat.py`、`views/chat_runs.py`、`models/agent.py`、`backend/agent/multi_agent.py`、`backend/agent/simple_agent.py`。同步 `POST /api/agent/chat/` 复用同一运行记录；上述增量事件属于流式入口。

### 2. 文档上传与入库（本地知识库路径）

1. 知识库页面向 `POST /api/agent/documents/` 传文件和知识库 ID。API 要求 `OPERATOR`，知识库按 workspace 查找，只收 `.md/.markdown/.txt/.pdf`；`target=ragagent` 是另一个远端转发分支，失败返回 502，不创建本地 `Document`/入库任务，以下仅述默认本地分支。
2. API 保存 `Document`（初始 `pending`，原文件在 storage），同事务创建有内容版本、代际和幂等键的 `DocumentIngestionJob(pending)`；返回 202、`document_id`、`task_id`、`task_url`。事务提交后投递 RabbitMQ；投递失败保留 outbox，beat 定期重投到期任务。
3. Worker 抢占租约后状态为 `queued → processing`，解析文件、切片、生成 embedding；成功时在事务中切换 `active_ingestion_generation`、置 `Document(ready)`、`Job(completed)`，清理旧代际。旧任务与重复投递受代际和状态检查约束，不能覆盖新索引。API `GET /api/agent/tasks/<task_id>/` 从持久任务表按 workspace 查询，`Document` 也有 `status`、`chunk_count` 和错误码。
4. 解析、embedding、超时或 worker 中断会进入有界 `retry`/租约回收，超过 `max_attempts` 进入 `failed`；若仍有旧有效索引，文档不一定整体失效。操作者可 `POST /api/agent/documents/<id>/reindex/` 创建新代际。删除文档需要管理员审批；文件与数据库清理不具备跨存储原子性。

代码：`frontend/src/features/knowledge/composables/useKnowledgeBase.ts`、`views/knowledge.py`、`services/ingestion_jobs.py`、`tasks.py`、`models/knowledge.py`。队列等待、重试及耗时以 `DocumentIngestionJob` 字段为准；真实 broker/worker 故障演练状态见 I-008。

### 3. 文章提交、审批与发布

1. `BlogView.vue` 向 `POST /api/agent/blog/articles/` 提交内容；已登录用户使用账号身份，访客须填昵称。API 按请求 workspace 创建 `BlogArticle(draft)` 和 `ApprovalRequest(pending)`，返回 202；这不是公开成功。已有草稿的发布入口 `POST /blog/articles/<slug>/publish/` 要求 `OPERATOR`。已发布文章的编辑要求 owner 或管理员/操作者并核对 `publication_version`，产生待审 `BlogArticleRevision`，旧公开版本保持可见。
2. 管理员在审批页调用 `POST /api/agent/approvals/<id>/`；服务端按 admin 角色和 workspace 锁定 pending 审批。拒绝置 `ApprovalRequest(rejected)`，未发布文章置 `rejected` 或修订置 `rejected`；批准执行受版本校验的发布事务，置审批 `executed`、文章 `published` 并递增公开版本。陈旧版本、重复审批或业务异常会得到冲突/`ApprovalRequest(failed)`，不得视为发布成功。
3. 只有选择加入知识库（或已有同步关联）时，发布事务更新关联 `Document` 并安排异步入库；**公开文章已发布**和**知识库索引就绪**是两个不同状态。匿名公开读取只返回当前 workspace 的已发布版本，未审修订不会进入公开页；作者和管理角色仍可经带权限的文章 API 查看私有稿。

代码：`frontend/src/views/BlogView.vue`、`AdminApprovalView.vue`、`views/blog_articles.py`、`views/governance.py`、`views/common.py::execute_approval_request`、`services/blog.py`、`models/blog.py`。访客投稿与操作者直接发起发布是不同权限入口；不把昵称当成认证身份。

## 技术决策与调整触发条件

| 选择 | 当前理由与成本 | 何时重评 |
| --- | --- | --- |
| Vue 3/Vite + Django/DRF 模块化单体 | 已有页面、权限、ORM、迁移和审批边界可复用；单部署代码库便于追踪一次业务事务。前端需处理路由/状态，Django 同步问答占请求 worker。 | 经实测的首屏、长请求吞吐、团队独立发布需要超出现有边界时，先优化局部路径；只有明确收益再比较 SSR/独立服务。公开文章的局部 HTML 决策见 I-017。 |
| PostgreSQL + pgvector | 业务行、workspace 条件和向量检索可在同库管理；JSON/SQLite 仅开发回退。迁移与索引维度需要维护。 | 用隔离真实数据库和标注集证明规模/并发下 P95 或召回不达目标，且索引/SQL 优化后仍不足，再评估拆专用检索；I-001/I-013 尚不足以宣称当前方案最优。 |
| RabbitMQ + Celery + 持久 outbox | 上传后解析/embedding 可离开 HTTP；持久任务、代际、租约和有界重试处理重复投递与暂时故障。代价是 broker/worker/beat 运维和最终一致性。 | 任务量、排队耗时或故障演练显示现有吞吐/恢复不足时调整 worker、队列或任务边界；不为普通同步 CRUD 增队列。 |
| Redis 缓存与结果后端 | 临时限频/缓存及 Celery 结果方便共享；权威业务状态仍在 PostgreSQL。引入失效与可用性问题。 | 实测命中率/成本或缓存故障影响表明需要改策略时；不以缓存代替权限复核、运行记录或入库状态。 |
| 有限 LangGraph | 沿用 I-007：当前保留 RAG 小图与正文流式事件，Supervisor 规则分发，未证明图相对普通函数有质量或性能增益。 | 若同条件评测显示图维护成本不值，简化为函数；只有真实跨请求人工中断、重启恢复需求和权限复核设计出现，才评估 checkpoint/HITL。聊天记录持久化不满足该条件。 |

新功能开始时使用[设计模板](templates/新功能设计模板.md)写清权限、状态、失败和验收；[I-017 填写样例](I-021-模板验证-I-017公开文章.md)展示其可用于实际任务。
