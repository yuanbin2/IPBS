# 通用网页剪藏定点修复与验收 V2.9.2

日期：2026-10-04。范围：当前 `browser-extension/` 通用网页剪藏 → 站内预览 → 私有笔记或博客草稿。保留旧力扣站内手动导入和既有数据；桌面默认端口仍为 5174。

## 复现与修复

| 问题 | 原因 | 本轮处理 |
| --- | --- | --- |
| 普通网页点击“读取并预览”失败 | `chrome.scripting.executeScript({func})` 只序列化 `extractFromDocument`，它依赖的模块函数未进入页面隔离世界 | 抽取器改为可重复注入的自包含经典脚本 `shared/extract-core.js`，popup 先注入文件再调用；独立 VM 双次注入回归 |
| 宣称 SHA-256 校验但篡改内容可接收 | worker 元数据无哈希，前端只在 ACK 后计算哈希，没有比对 | 暂存时计算哈希，meta 发送摘要，前端逐片限流并在 ACK 前比对；缺失、错字节和错哈希失败 |
| 两条过期剪藏后不能继续 | pending 列表过期不清理 | 发送前清理过期/已消费记录，ACK 清除正文并保留无内容的重放标记 |
| 私有笔记格式丢失 | HTML 在前端被剥为纯文本且静默截断到 50,000 字 | 私有笔记也走既有服务端 HTML 安全预览与逐块选择；超长提示减块，不截断 |
| 图片丢失或相对图指向本站 | 抽取器拒绝相对图片，懒加载图优先取占位 `src`；笔记前端未接私有图片接口 | 相对图按原网页解析，优先真实懒加载地址；用户确认后上传/下载到私有附件，笔记保存时绑定；编辑器用认证 fetch 的 blob URL 显示并在保存时还原私有 URL |
| 私有图片可能经静态 `/media/` 访问 | 旧 `private_note_media` 实际位于 `MEDIA_ROOT/private-notes` | 默认移至公开 media 外，DEBUG 路由与 Nginx 对旧目录直接返回 404，E2E 也使用隔离目录；认证读回返回具体 MIME 和 no-store；提供已存文件的校验搬迁命令 |
| 扩展入口仍写“仅力扣”，受限网页提示可手动粘贴但输入框只读 | manifest/提示未随通用剪藏更新 | 更新名称、版本和受限页回退文案；只采集当前活跃标签页，失败时引导用户另存 HTML 到站内导入 |
| 点击“送到博客”时报 `storage.set` 参数签名错误 | v2 流程把 `chrome.storage.session.set` 误当成 `(key, value)`，而浏览器要求 `{ [key]: value }` | 所有 pending、正文暂存、目标标签绑定、ACK 清理都改用浏览器原生对象签名；单元测试的存储模拟也严格拒绝旧签名 |
| 博客页报“剪藏处理失败”且看不到发生在哪一步 | 扩展后台把所有意外异常合并成同一提示；另外元数据用总字节数除以 64 KiB 估算分片数，在中文边界可能少算 | 后台错误提示区分读取/传输/确认阶段并在扩展 Console 保留原异常；旧版不完整暂存返回重新加载提示；片数按实际 UTF-8 分片计算，分片扫描改为线性时间。版本提升为 0.2.1，需在扩展管理页重新加载并重新发送 |

## 本地验证

- `node --test browser-extension/tests/*.test.js`：31/31，包含独立隔离世界执行、二次注入、SHA 元数据、过期队列、UTF-8 边界片数、旧暂存记录错误与抽取规则。
- `python manage.py test apps.agent_api.tests.test_private_notes apps.agent_api.tests.test_html_import --keepdb`：38/38，包含私有图片鉴权、MIME、目录隔离及旧文件搬迁演练。
- `npm run build:check`、Ruff、Black、`makemigrations --check --dry-run`：通过，无新数据库迁移。
- 隔离 Edge 使用假扩展消息的网页剪藏 E2E：6/6；分别验证默认私有笔记显式保存、博客草稿、失败路径、私有图片上传/绑定/刷新读回和忽略失败远程图片只留文字。此项不覆盖实际工具栏弹窗与 `activeTab` 授权。
- 本地真实业务库 `PrivateNoteImage` 为 0；搬迁命令只读预演显示 `would move: 0; already private: 0; missing: 0`，未改原目录。生产或其他环境必须先跑预演，再按备份策略执行 `--apply`。
